# 租户即时授权与角色工作区

## 拥有者与当前角色

IAM 按当前组织的 `ownerMemberId` 及有效成员、账号状态识别拥有者。拥有者动态取得有效开通应用的权限，目录新增操作按当前授权事实纳入；创建组织不写固定拥有者角色分配。转交按 [组织设置](../tenant-settings/SPEC.md) 执行。

平台维护共享角色，租户只读。租户可直接创建和维护本组织私有角色。两类角色以完整当前权限定义生效，保存含资源字段权限的内部快照。租户分配引用角色 ID，角色保存后后续请求按当前权限计算。已有兼容范围绑定保留；新增必填绑定缺失只关闭受影响操作。平台自有角色继续走 [固定版本与批量应用](../role-version-application/SPEC.md)。

## 分配与委派

成员直接分配与组继承分别按主体、期限、角色状态和范围求值。组按当前任职展开已绑定部门及启用的下级范围。受限管理员必须绑定本人单一有效委派来源。资源范围与角色白名单持续取交集，同资源新增操作可以跟随，新资源须补齐上限。撤销、到期、自我授权和越界请求按服务端规则处理。

租户请求、消费 SDK 和旧快照入口按请求重新读取有效授权事实。请求内可复用计算结果；依赖失败时关闭授权。角色字段与租户策略的组合见 [租户资源字段策略](../tenant-field-policy/SPEC.md)。

成员列表按租户与对象读取范围同时过滤记录和总数。具备成员读取操作的身份读取范围外、外租户或不存在的成员详情时，统一返回 404「成员不存在或不可访问」。缺少所请求操作资格时返回 403。

## 普通成员的应用开通与人群

普通租户成员的授权求值按已校验的租户、成员和去重后的候选应用，最多执行一条 SQL 批量判断应用开通、有效期及人群。候选应用为空时跳过查询。开通期限包含开始时刻、排除截止时刻，支持不限期。人群按全组织、指定成员、用户组及部门配置求值，保留组继承和部门下级规则。未命中的应用不纳入本次授权。

`GET /v1/me/capabilities` 使用该求值结果。`GET /v1/me/bootstrap` 装配可用应用列表时最多再执行一条同类批量查询，保留应用排序。两次读取均基于当前数据库事实，开通和人群的变更提交后在下一次请求生效。拥有者按有效开通应用实时求值，适用既有的人群例外。

## 工作区与诊断

`GET /v1/tenant/roles/{id}/members`、`/groups` 和 `/members/{memberId}/assignments` 在角色可见和分配读取授权下独立分页。成员直接和组继承来源去重，来源数量按当前可见关系计算。成员部门按权限附带；受限管理员只读本人委派来源，分配详情仍负责最终状态判定。

角色权限目录按所选应用返回完整已开通操作和资源字段能力。租户诊断候选通过 `GET /v1/tenant/authorization/diagnose/candidates` 按成员、应用、操作和目标对象查询，候选受当前身份、应用开通和对象读取范围约束。
