# 角色版本信息与批量应用

## 版本与元数据

平台自定义、共享和租户角色版本具有 `versionName`、`remark` 和独立的 `metadataVersion`。名称最多 128 字，备注最多 512 字，名称不要求唯一；未填写名称及历史版本回退展示 `vN`。版本 ID 和系统版本号始终保留，不以名称建立引用。系统角色保持只读。

版本的操作授权、范围表达式、参数定义、租户定制差异、固定共享基础和字段权限保持不可变。角色分配始终引用固定版本，发布新版本不会自动改变分配。名称和备注通过元数据乐观锁独立修改，需要角色既有更新资格并记录审计；不会发布权限版本、修改分配或清理授权缓存。展示查询直接读取数据库，没有独立版本展示缓存。

创建首版、发布和租户共享基础升级均支持版本名称及备注。发布可指定同一角色的 `sourceRevisionId`，历史版本详情和授权快照可用于编辑。租户定制发布采用所选来源的固定共享基础，保留定制差异与字段权限，不自动切到最新共享基础。

## 管理接口

平台、共享和租户管理路径分别为 `/v1/platform/roles`、`/v1/platform/shared-roles`、`/v1/tenant/roles`。它们提供固定版本详情、固定版本授权快照及元数据修改接口。版本详情需要角色 READ；元数据修改沿用角色 STATUS 更新资格。

平台应用入口为 `/v1/platform/roles/{roleId}/version-applications`，提供准备已有版本、发布并准备、分页任务记录、分配候选、版本分布、计划详情、分页明细、范围及排除配置、重新预检和确认执行。管理台通过 `/api/iam` 网关前缀调用。

响应沿用 `R`、`ResourceDetail` 与 `PageResponse`；标识、版本锁和大计数字段使用字符串，时间点使用 UTC ISO-8601。分页默认 1/20，最大 200。完整契约由 Java DTO 与控制器生成，接口说明见本能力 README。

## 应用集合与治理资格

批量应用只支持平台自定义角色的已发布版本，允许更高或更低版本。所有应用能力需要独立的 `iam-platform:assignment:upgrade` 治理资格，并验证角色 READ 和对象范围；发布组合入口还检查角色发布资格。角色编辑权限本身不能执行应用。

集合选择包括全部关联分配、指定来源版本和指定分配。处理单位是分配记录，成员直接分配与用户组分配均保留原主体，不展开组成员。纳入 ACTIVE 且未到期的记录，未来生效时间保持不变；撤销、到期和已经为目标版本的记录分别统计。

服务端按角色关联查询建立游标快照，前端不拉取全部用户。快照后新增分配不自动纳入；原记录变化不得直接覆盖。全部及来源版本集合要求治理范围覆盖整个有效集合；指定不可见分配返回对象不存在。候选、明细和计数采用同一可见性边界。

## 范围与预检

参数键、类型和关联资源兼容时保留每条分配的原绑定，移除目标版本不再使用的键。新增或不兼容参数必须补齐，不默认赋予全部范围。支持逐条、选定集合和整个集合明确覆盖参数；没有覆盖的兼容绑定继续保留。

动态范围按实际身份和关系计算。逐条验证目标版本可分配性、主体、期限、范围归属及来源委派，不自动扩展委派白名单。影响预览比较操作、范围表达式、参数绑定和字段权限，不以版本号判断权限扩大或缩小。

发布并准备在同一事务保存版本与计划。冲突时新版本保留，分配零更新，任务进入 BLOCKED；补齐范围或明确排除记录后重新预检。确认时再次对全部未完成项使用最新事实预检，只允许 READY 计划执行。

原升级分配接口仍最多处理 100 条，只允许更高版本，并与应用流程共用范围复用、委派校验和写入门禁。

## 持久任务与执行

`iam_role_application_task` 保存角色、目标版本、可信发起账号和平台成员、集合快照、任务状态、计划锁、幂等键、租约及失败原因。`iam_role_application_item` 保存原分配版本与范围、预期分配锁、配置覆盖、预览、明细状态和失败原因。不保存登录令牌。

任务状态为 PREPARING、READY、BLOCKED、RUNNING、PAUSED、SUCCEEDED；明细状态为 PENDING、BLOCKED、SUCCEEDED、EXCLUDED、REVOKED、EXPIRED、ALREADY_TARGET。准备幂等键按角色约束；确认使用计划乐观锁及确认幂等键。

多节点使用数据库 UTC 时间和 30 秒租约领取任务，同一角色最多一个 RUNNING 任务，事务内锁及领取校验防止过期节点覆盖。每批最多 100 条，沿用授权、角色、分配的锁顺序。分配更新、明细结果及审计同事务提交。

工作批次从保存的身份标识恢复当前有效身份，再次检查治理资格、分配版本、目标、范围和委派，不依赖 HTTP 线程身份或预览时的授权。冲突、撤权或依赖故障回滚当前批次并暂停后续执行，已提交批次保留。继续处理必须重新预检未完成项并再次确认，不自动恢复已完成分配。

存在应用任务历史的角色不能物理删除，保留任务和审计引用。`ingot.iam.role-applications.worker-enabled` 默认 true，可关闭本节点领取。任务持久状态决定恢复进度，浏览器关闭不会停止任务。

## 引擎职责与扩展边界

`RoleApplicationScheduler` 通过内部 `RoleApplicationWork` 调用任务发现与单批执行；`RoleApplicationService` 实现该接口，管理集合快照、配置、预检编排、幂等、持久任务及明细状态、租约、事务和提交后提示。

共用服务通过 IAM 内部 `RoleApplicationDomainSupport` 接口调用业务规则。当前仅有 `PlatformRoleApplicationDomainSupport`，使用构造注入，不设置注册中心或运行时域路由。平台适配器封装治理准入、当前有效身份恢复、普通读及 fresh 范围、角色归属与 READ 校验、版本访问、授权及角色锁，以及分配查询、快照、预检和写入；复用既有 IAM 服务与 Repository。事务仍由共用流程管理，适配器不增加查询、事务或准入缓存。

该接口属于 IAM 内部扩展边界，不是公共任务框架。当前任务没有租户上下文，平台适配器拒绝非平台身份、非平台自定义角色及不同角色目标，不能依靠替换接口直接开放租户执行。租户应用或独立 App 用户授权需另行确定持久上下文、路由及治理门禁；App 客户端本身不构成新的授权域。

角色 worker 不调用 TSS API；`ingot.tss.type` 在 Spring 与 XXL-JOB 间切换不控制角色 worker，角色应用也不注册为 XXL-JOB Admin 任务。当前 TSS 提供 Cron 调度与管理，角色 worker 使用提交后立即唤醒、按 ID 续批、扫描错峰及错误退避，两者独立运行。未来接入 TSS 时只能以发现或唤醒为入口，须消除重复扫描并保留这些时序语义；TSS 触发成功不能替代角色任务完成、数据库租约或当前授权校验。

职责分离不改变 API、DTO、任务结构、配置、事件、缓存或调度契约，无需数据库迁移或前端升级。新旧节点共用既有任务与租约，代码回退仍能读取原任务、进度和审计。

## 调度与多节点运行

确认计划进入 RUNNING 的事务提交后发布本地提示，本节点立即按任务 ID 排队；回滚、未确认的发布及幂等确认重放不产生新的提交提示。本地排队后，通过独立有界发送线程异步广播 `iam.role-application.wakeup`。远端节点收到提示后随机延迟 200～1000 毫秒，再查询任务主键、租约和当前身份；提示不承载授权，也不能直接恢复 PAUSED 任务。

定时器、扫描、单批执行、通知发送及订阅分别使用独立线程，生命周期由 Spring 管理。角色 worker 不通过 TSS 注册，不共用 HTTP 或 TSS 任务执行线程。每个开启 worker 的节点都能扫描和领取，不选主；多节点互斥继续由数据库租约、角色唯一 RUNNING 约束及事务内校验保证。

本地队列按任务 ID 去重，执行中保留标识，同一节点最多执行一个批次。剩余明细按配置间隔重新排队，按 ID 续批不重新扫描任务集合；执行中到达的新提示在批次结束后合并处理。队列容量有限，溢出只丢弃提示，持久任务及明细仍由数据库保存。

配置前缀为 `ingot.iam.role-applications`，修改后重启相应节点生效：

| 配置 | 默认值 | 约束与语义 |
|---|---|---|
| `worker-enabled` | `true` | 控制本节点接收和执行任务提示；关闭后 HTTP 确认仍可向其他节点广播 |
| `fallback-scan-interval` | `60s` | 正常扫描完成到下一轮的间隔，至少 10 秒；首次扫描在该间隔内随机错峰 |
| `active-batch-delay` | `250ms` | 未完成任务续批间隔，必须为正且小于 10 秒 |
| `queue-capacity` | `256` | 本地提示队列及异步发送队列容量，必须为正数 |

非法配置阻止启动。扫描只读取任务 ID 和角色 ID，按 ID 游标分页，每页最多 100 条；队列满时保留游标，下轮继续，遍历结束后回到起点。无任务时每节点默认约一分钟一次发现查询，有大量任务时一轮可执行多页 SQL。扫描失败按 60、120、240、300 秒退避，成功后恢复配置间隔。

事件总线缺省、Redis 故障、通知重复或丢失时，本地确认及数据库兜底仍有效；网络发送与订阅不阻塞执行和扫描。全部 worker 关闭时 RUNNING 任务留在数据库等待恢复，不转到 HTTP 线程执行。数据库健康且队列无积压时，本地确认后目标 1 秒内开始领取；默认故障接续发现窗口约为 30 秒租约加 60 秒扫描，积压、数据库故障和自定义间隔会延长窗口。

停止时不再接收提示或安排新批次，取消定时及订阅，最多等待当前批次 30 秒；超时不强制中断正在提交的事务，异常退出由其他节点在租约过期后接续。业务冲突和撤权仍暂停，已提交批次保留，继续执行仍需显式重新预检和确认。

Micrometer 指标统一使用前缀 `iam.role.application.`，后缀包括 `discovery`、`discovery.errors`、`lease.conflicts`、`batch.duration`、`batch.errors`、`queue.depth`、`hints.dropped`，数据来自现有流程，不增加监控 SQL。队列深度包含当前执行项，领取冲突记录事务内竞争失败；故障 WARN 限频，普通空扫描无业务 INFO。

调度优化不增加数据库结构、前端或公开 API。可滚动升级，全部旧 IAM 节点退出后才完全消除原每秒扫描；回退保留现有任务、进度、审计及租约契约。

## 缓存与兼容性

每批提交后复用既有授权和字段缓存失效通知；普通读取遵守当前最长 30 秒缓存窗口，准备、配置、确认及执行使用 fresh 校验。权限降低只改变该角色贡献的授权，其他角色权限继续合并。

权威 DDL 和完整初始化文件包含版本信息、任务存储和必要索引。已有库使用 `017_role_revision_application.sql` 增量升级；脚本可重跑，不重写历史权限、分配、范围或版本引用，006 目录初始化不能代替结构升级。

发布顺序为数据库增量、全部后端节点、前端。回退前停止新任务确认和全部节点领取，确认当前事务结束，处理剩余运行任务；保留新增列、表、明细和审计。已完成权限调整通过新的版本应用操作恢复。

## 当前授权与版本摘要

平台、共享及租户角色的当前授权接口一次返回完整 `items`，并可附带 `revision: RoleRevisionSummary`。摘要包含字符串固定版本 `id`、字符串发布序号 `revision` 及可选 `versionName`；版本标识与角色乐观锁分别使用。服务复用同一次最新版本查询生成摘要并加载授权，不再重复按主键查询该版本，也不计算历史差异。

无发布版本时 `items` 为空且省略摘要；已发布但无授权的版本仍返回摘要。固定版本授权快照保持完整 `items`，可省略摘要。当前授权与摘要始终来自同一固定版本，前端不通过历史分页确定最新版本；完整编辑来源按摘要中的固定版本 ID 读取。

本契约为兼容的响应扩展，旧前端可忽略新字段。前后端联合部署先后端再前端；回退后端时同时回退依赖摘要的新前端。没有数据库、请求参数、权限、治理范围或错误码变更。
