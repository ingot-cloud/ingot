# 剩余环境验收需求

本记录承接原 A01–A24 中尚缺目标环境证据的部分，并关联后续已经完成的 IAM 与前端验收。入口、接口和安全规则沿[同源登录基线](../../../current/security/same-origin-login/SPEC.md)，发布方式按新系统首次部署执行。

## 部署与验收范围

- 平台、租户各一个浏览器 origin，每个入口同时提供 `/login/`、管理页面与同源 `/api`；不新增登录域。BFF 内部 OAuth 回调不是额外浏览器站点。
- 默认双 HTTPS 域名。纯 IP HTTPS 双端口仅在目标选择该模式时验收；未选模式记录为不适用及原因，不记为测试通过。
- 已验收的本地能力及证据见 [DESIGN](./DESIGN.md#已有证据与剩余边界)。目标环境检查限定为部署配置核对、必要冒烟及尚未覆盖的环境差异，不重复要求本地全量功能验收。

## 需求与验收标准

| 编号 | 需求 | 验收标准 |
|---|---|---|
| R01 | 实际入口、TLS 与会话边界（A02/A23） | 所选模式的 CA 根信任、DNS/IP SAN、反代 Host/端口、静态深链、未知入口拒绝及两应用独立登录/退出通过。登录和 API 不跳转独立登录站；API 错误不回落 HTML。IP 模式允许两套 Cookie 随同一主机请求发送，仅按当前应用消费与清理，不能声称端口隔离 Cookie 发送。 |
| R02 | 真实长停留及休眠恢复（A03） | 记录真实一小时/隔天停留及机器休眠恢复的起止时间、浏览器状态和登录结果。无进行中事务时不创建事务或心跳，恢复后可按当前身份/期限正常登录或明确重新登录；虚拟时钟不替代实际经历。 |
| R03 | 目标安全与故障链路（A05–A09/A11–A21 的未覆盖部分） | 逐项关联资格撤销、锁定/禁用、重置/强制改密、踢出、异浏览器重放、网络及 Auth/IAM/Redis 故障的已有证据；补测目标环境缺口。结果符合现行拒绝、503、有界恢复及补偿规则，不把受控夹具或本机证据记为目标环境实测。 |
| R04 | 首次部署与失败恢复（A24） | Auth/BFF/Gateway、两份前端、Nacos 注册与反代版本匹配，入口冒烟及补偿监控有效；演练并记录本次部署失败后的停止发布、成套回退或修复重试路径，恢复后重新核对入口与身份。无已验证旧版本时不假定可恢复四站；仅在实际存在旧系统时增加旧 Cookie/Redis 的定界盘点、撤销和迁移步骤。 |
| R05 | 证据与签收 | 每项记录环境、版本、执行者、日期、证据类型、结果及失败处置；不适用项说明条件，缺少证据的项保持待验。用户确认实际发布/恢复结果后再完成归档。 |

## 非目标

不新增认证功能、外部 OAuth2/SSO、四域兼容或旧库迁移；不重开已完成的登录外观验收。本轮不执行生产操作、破坏性重建或账号状态变更。后续实际部署及故障演练按 E00 确认的环境和操作范围执行。
