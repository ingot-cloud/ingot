# Design

## 文档与兼容

权威 DDL 为唯一字段说明来源；解析 CREATE TABLE（支持引号、嵌套表达式与行内主键），生成数据字典和已有库注释脚本。说明包含业务对象、归属、NULL/默认、枚举、JSON、UTC、OSS、生成列约束。现有主键/索引/默认值/类型/外键保持原样。

注释升级使用显式选库的 mysql 客户端。开发期在无网络临时 MySQL 生成结构快照；升级的只读预检比较目标与该参考 SHOW CREATE（忽略 COMMENT、运行时 AUTO_INCREMENT、约束排序及已验证的ASCII字面量引导符规范化；列字符集、排序规则及表达式仍严格比较），并验证源结构摘要；全部目标表匹配才允许执行生成的 COMMENT ALTER。预检不创建任何数据库；提供 check-only 和 apply，连接凭证通过 mysql 配置文件传递。禁止忽略错误，禁止自动修结构。ALTER 按表组合，定义从权威源保留，重复执行稳定；回退应用不必回退注释，必要时用原说明重生成。

## 差量持久化

成员部门共享 MemberDepartmentWriteRepository；现有两个 Repository 委托，不改变调用方授权与事务。读取旧关系并按完整键比较，先取消需要变更的旧主标记或删除移除项，再插入新增项并更新保留项中变化的主标记；新增项直接携带目标标记，避免首次绑定多一次UPDATE；未变化行不写。已有事务/组织和成员锁保持。

组保存读取完整旧集合，以成员 ID、部门 ID 比较；保留原关系，include_descendants 仅变化时更新。菜单/套餐按 ID 集合增删。重复输入仍拒绝，不能通过 Set 静默去重。删除业务对象的清空入口保留。负责人只在主成员变化时清旧/设新；新增仍非主写入。父版本、审计和授权失效维持各自原语义，不统一改成空操作。

不新增通用缓存、关系框架或公共 DTO。新增依赖按 private final 构造注入及 JavaDoc 规范。

## 评估与验证

全表清单从 manifest 生成结构基础，逐表补业务入口、聚簇顺序、二级索引及外键成本、发号方式和风险说明。结论仅保留/候选优化/需要运行数据验证。本轮不改主键。人群/整体开通/委派/快照记录保留原因。

复用生成漂移和 MySQL schema 测试；补全注释覆盖、升级幂等及结构漂移拒绝测试。真实 MyBatis 结合 SQL 拦截计数，验证集合差量、无效更新、主标记切换和回滚；生成列及并发使用本地无网络隔离 MySQL，不连接实际业务库。部署顺序为可选注释升级→后端；后端可独立回退，保留关系数据。验收后再更新 current 并归档。
