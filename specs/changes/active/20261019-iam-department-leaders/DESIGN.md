# Design

## 已批准实现

新增 iam_department_leader，复合主键 tenant_id/department_id/member_id，is_primary、复合租户外键、唯一主负责人约束及成员反查索引。复用部门version和现有事务审计，不增加授权状态。

关联分页 SQL 直接 JOIN 关系与成员/账号，并应用现有 member:read ObjectScope；候选为有效、未绑定人员，同范围搜索和计数。显示名遵守成员管理字段策略，接口不返回登录手机号、手机、邮箱或账号信息；名称检索必须有完整字段检索资格。

新增 DepartmentLeaderService/Repository，private final 构造注入。写入以租户组织锁→部门→按ID排序成员锁串行化，事务内重验身份、读/写操作和对象范围、版本，按增删差量更新，唯一主负责人转换先清原主后设置新主，审计失败全部回滚。角色和授权表不读写负责人关系。

部门管理服务批量查询关联摘要，无N+1；隐藏成员不返回姓名/ID/总数。不可用由成员 ACTIVE 及账号启用/未删除计算。既有不可用主负责人不自动换人，允许未变更保留。

新操作 iam-tenant:department:leaders 归属department资源，IamActionOperation登记leaders写语义；ObjectCapabilities及正式目录/升级脚本/OpenAPI/前端常量同步。普通角色不自动补权，拥有者沿既有动态权限。

前端沿用部门列表及详情抽屉，新增负责人列；详情取消 Tab，基本信息与负责人统一编辑、原子保存。组织成员对话框提供部门导航与成员候选，部门不可选择；关系分页默认20，新增、移除、设主形成差量，未加载或受限关系不丢失。409保留草稿不重试，成功刷新详情及列表摘要。

## 宪章符合性

业务UI位于org插件；公共IAM类型/操作常量位于admin-common；复用现有In组件、主题和网络层，无跨插件依赖。使用现有字段投影、SQL对象范围、构造注入、JavaDoc及业务枚举规范。

## 兼容、迁移、回滚

独立增量迁移先于新版后端/前端；权威DDL和新库生成源同步。既有关系为空，不从角色反推负责人。新增目录不修改普通角色分配。回退应用保留关系表和审计，不重建数据库。验收前不修改current。

## 2026-10-19 已批准修订：统一表单与组织成员选择

用户明确授权更新 Spec、skill 后实施。上一版独立负责人 Tab 和平铺选择器被本节替代；已完成的关系模型、唯一主负责人、差量、字段/范围校验、停用保留规则继续有效，无新数据库迁移。

- admin-core 的 InDetailDrawer 增加明确无 Tab 模式及字段组可编辑入口，默认行为保持兼容。
- 部门详情将两类字段放入同一草稿。PATCH /v1/tenant/departments/{id} 接收 expectedVersion、可选 department 与可选 leaders 差量。同组织锁→部门锁下检查同一版本，按实际变化分别验证 action/对象范围；两个部分同事务保存与审计，部门版本只递增一次。原 PUT 及 PATCH /leaders 保留兼容。失败全部回滚，409 保留草稿。
- 通用组织成员录入框及对话框放在 admin-common。复用现有选择草稿、分页和关联回显逻辑，通过显式组织导航配置及场景候选 loader 接入；不把平台选择器全局改为组织树。
- 左栏组织根显示全部当前可选成员；展开部门后只看该部门直属候选，子部门可继续展开，面包屑返回。关键词非空时在同一候选边界内跨部门搜索；清空恢复原分支。部门不可选，全选仅本页可选成员。已选ID/名称快照跨分支独立保存，关联规模的旧选择单独分页，差量保存不覆盖隐藏或未加载关系。
- 新增部门导航分页接口，沿用 department:read 和现有对象范围。只返回允许部门；范围不连续时从可见片段入口导航，不披露隐藏祖先名称。无此操作时前端根入口仍可使用各业务既有人员候选，不请求部门数据。
- 新增通用最小成员候选接口，沿用 member:read、成员范围及字段投影，只提供姓名检索且须有原文检索资格。有效候选需 ACTIVE 且账号可用。少量已知 ID 回显可保留已存在但不可新选的成员，并标记资格；不借更宽列表补名称。
- 负责人及当前角色分配/委派候选增加可选浏览部门过滤（与正在维护的目标部门ID区分），在 SQL 分页/计数前与原候选范围相交；过滤部门须可读。未传参数保持旧响应/行为。
- 组织选择器通过租户组件上下文提供部门 loader；通用成员录入框接收候选 loader。现有租户页面及共享组件的人员路径接入；平台、非人员对象不变。用户组/策略中选部门作为动态来源仍使用独立部门选择，不混入人员结果。

规范唯一来源为前端 in-coding-standards 下 tenant-member-picker.md，并从主 SKILL 及实体交互规范引用。同步维护自动验证和人工验收，不提前更新 current。

兼容现有用户组等完整草稿接口：在原始完整ID集合上合成选择差量，不改变既有提交契约；已绑定成员另走组关联分页展示，不能用首屏回显替换未加载关系。负责人仍以服务端增删差量保存。


## 2026-10-19 飞书对照精修（用户本轮明确批准）

以用户提供截图及飞书实页核对成员对话框：宽840px、多选等宽双栏、内容高420px、正文14px/22px、行高48px、头像32px、栏内间距16px；外层24px边距，底部按钮80px，窄屏收缩。使用框架主题的文字/边框/悬停/主题背景与主色，不写死飞书蓝。

- 搜索下方展示组织名称和当前部门面包屑，用右箭头分隔，末级仅文本，祖先可返回。组织名称仅在当前部门读取范围可见时返回，否则“当前组织”；禁止借完整树补隐藏祖先。
- 勾选文案“全选”，仍只作用于当前加载页的可选人员，不选择部门、不隐式拉全量。部门用32px组织图标圆底，成员用32px头像/姓名占位，候选与已选复用一致图像；行可点击、键盘可操作、悬停有反馈。
- 右栏有选择后显示“已选：N 名用户”和“清空”，姓名下方显示该成员实际任职部门（可多部门），来自候选/绑定页的受限投影；选择和切换主负责人时不另行查询成员详情。为空时留白。
- 部门负责人扩展：标题“请选择”；有多个负责人时顶部提示“可选择多位部门负责人，必须有一个主负责人”；首位从空集合新增的有效成员自动成为主负责人，其他人可用“设为部门主负责人”切换，“部门主负责人”为主题浅底标签。用户在草稿中移除当前主负责人时，优先将首位已知且可用的剩余成员设主；没有可操作剩余成员则要求继续加载/明确选择。既有受限或不可用主负责人不能仅因打开对话框而自动更换，账号状态变化也不自动继任。
- 搜索文案仅声明已实现的姓名检索，不虚示邮箱/手机号/ID检索。默认授权、数据范围、字段策略与Token契约保持不变；自动设主仅是负责人表单草稿默认值，确认后仍等待外层保存及后端重验。
- 负责人候选/绑定返回departments最小任职投影；当前角色分配成员候选可返回同样的部门信息，须同时满足既有成员与部门读取范围，不能扩大原候选池或为复用而补权。导航增加可选organization名称对象；旧字段和路径保留，无数据库迁移。

## 用户批准的选择器专用浏览修订（2026-10-19，用户已授权）

新增 GET /v1/tenant/member-picker/browse，以 MEMBER / DEPARTMENT_LEADER / ASSIGNMENT 场景复用原有候选资格，返回部门导航与成员两个独立分页。目标部门与浏览部门分别传递，委派来源继续限制接收成员。根分支采用 EXISTS 根关系 OR NOT EXISTS 本租户任何关系；普通部门仅直属，条件在 SQL 计数/分页前应用。搜索忽略分支但保留原场景边界。无部门读取资格不返回部门信息，保留原候选池并显示“可选成员”；根不可见的局部部门范围初始只显示可见部门片段，选择具体分支后显示直属人员。任职返回真实可见关系；仅确实没有关系且成员/根均可读时增加 implicitRoot 显示投影，不写入数据库。原列表、直属人数、绑定关系分页、权限、字段、token均不变；无需迁移。前端候选、导航共用一次请求，分页独立，跨部门选中按成员ID同步，旧绑定分页保留。复选框使用框架尺寸变量并保留 Element Plus 原生居中位移，去掉固定 left/top 偏移。

实现核验：任职与 implicitRoot 的成员读取范围均在 SQL 中校验，保留“指定成员ID AND 部门集合”等交集，禁止仅靠内存ID命中判断。半选使用 top:50% 与一次 translateY 适配框架16px；勾号沿原生居中。服务端返回无部门资格时，前端使用“可选成员”，不受旧客户端权限快照影响。

## 姓名搜索接入修复（2026-10-19）

已批准的姓名搜索校验要求完整可见且允许筛选。实际缺口为租户 member.displayName 的注册描述、目录上限、FILTER执行清单均未开放。补齐该资源能力及keyword到displayName的FILTER声明，保留所有原操作和SQL对象范围。默认策略的操作上限在未显式配置时支持已接入姓名筛选；明确配置false仍拒绝，普通用户已有默认/租户规则不自动打开，拥有者仍服从平台能力/操作上限。通讯录、平台域及角色/token保持原语义。增量025只补齐租户成员目录的displayName能力，不改角色、分配、历史默认策略版本或租户规则；新库生成源同步。部署需同版本后端及025；未执行迁移时继续fail-closed。

负责人关系分页与可新增候选分页保持独立。browse中的page/pageSize用于候选人员，departmentPage/departmentPageSize用于导航部门；/leaders的page/pageSize用于已有负责人，未加载及不可见关系继续保留。

## 已选快照复用与追加加载（用户批准）

右栏默认使用外部完整数组草稿。关联模式可传initialBoundPage（records、total、current、size），附已有ID、增删差量及主负责人。传入首屏快照时不重复查第一页；完整可见集合不发右栏请求，部分集合从快照current+1继续。缺少快照的既有loader调用保持兼容。确认回填原有值/差量，并返回最新已加载关联快照供父表单复用；取消不改父草稿。权限/身份/部门/版本变化失效快照与旧请求；受限及未加载关系继续差量保留。

租户组织模式候选改为逐页追加，保留默认20；部门与人员独立推进。实际滚动到相应区段底部时加载下一页，保留可点击加载更多/失败重试；右栏部分关联同样追加，完整数组只滚动。加载更多统一轻量文字按钮、居中、上下留白，加载中禁重复，加载完不留下按钮/空白区。只有已加载不足total且服务器页号尚未到末页且上一页非空才有更多；过滤移除不影响原集合的已加载计数。重复ID去重、不根据去重后数量无限追加。失败保留旧数据，重试失败页，迟到响应不污染新分支/搜索/会话。

全选文案保留“全选”，组织追加模式只处理当前分支/搜索已加载的可选人员，不包含部门或未加载全组织成员；跨分支已选保留。平台模式继续原分页及交互。接口及操作/数据/字段/token边界不变，无后端接口或数据库变更。

## 部门详情聚合（H01-H04）

在既有DepartmentRecord添加可选parentDepartment（id/name）及leaderPage（DepartmentLeaderPage）。仅管理详情/更新返回，列表、通讯录与导航不装配；保留旧构造器/字段。上级用同租户department:read范围的SQL查询，不借无范围find或完整管理树补隐藏名称。负责人首屏复用关联SQL、默认20、成员读取范围及原始字段投影；缺少member:read时不查人员、不填leaderPage，保留restricted摘要。详情与PATCH/PUT返回同一聚合，后续页沿/leaders，候选沿/member-picker/browse。首屏复用已求得摘要，不再重复统计。无DDL、默认授权或Token变更；旧客户端忽略新增字段，服务端回滚停止装配，前端旧加载方式保留为非聚合调用兼容。

InDetailIdentity增加可选avatar槽，默认头像/上传行为不变；部门提供56px主题圆底DepartmentMark，不提供上传。MemberDepartmentField扩展multiple=false单栏radio模式，与多选共用部门树、搜索、加载/重试和主题样式；保留多选默认及拖曳主部门。excludeDepartmentId仅禁选自身及子树，仍可展开导航，navigationOnly禁选。录入框键盘可聚焦，名称快照由详情传入，不为回显加载完整树。树在打开时按既有接口加载，同一上下文复用，身份/权限变化清空缓存并丢弃迟到结果。确认才修改外层草稿，提交仍用parentId及原expectedVersion。

旧PUT仅有update或其read范围不覆盖当前部门时保持原可调用性，省略新增聚合信息，不为显示上级或负责人补充读取资格。

## 组织选人HTTP参数分类修复（B01-B03）

FILTER拦截器检查完整query，不能仅声明keyword而遗漏已批准的场景、目标、导航和分页参数。browse、成员picker、负责人绑定分页与旧候选接口分别使用与本接口参数完全对应的分类DTO：keyword继续绑定member.displayName FILTER，场景/引用/分页显式标为PublicField。只修正合法控制参数的分类；服务层继续验证场景资格、引用范围及页大小，未知参数及属于其他接口的参数仍返回InvalidArgument，不删除或放宽框架拦截器。无新增路由、参数、授权、DDL或Token属性。

验证使用实际控制器注解、FieldBindingRegistry与FieldFilterInterceptor的MockMvc HTTP请求覆盖用户提供的完整URL、默认参数、三场景、部门导航/姓名搜索/分页、另外三条复用入口、未知参数拒绝以及业务ActionDenied透传；现有字段求值/SQL/元数据测试保持通过。

## 负责人头像投影（V01-V03）

DepartmentLeaderRow查询本次SQL范围内的m.avatar，摘要只聚合主负责人对应头像；不回查全员或逐人详情。DepartmentLeaderService将原始头像与姓名一同放入MemberRecord，经FieldAccessEvaluator原member读取字段策略投影后装配DepartmentLeaderRecord.avatar。OrganizationMemberService的当前页成员查询同样补选/投影avatar；browse将MEMBER/DEPARTMENT_LEADER已投影头像透传到OrganizationMemberPickerOption，并在implicitRoot再装配时保留。ASSIGNMENT沿原投影不新增资料。

两个DTO增加可空avatar及兼容旧构造器，输出采用IAM已有Jackson ReadAvatar mixin的@OssUrl；库存仍为bucket/objectName，没有新写接口或DDL。隐藏字段始终为空；不从账号头像或更宽接口回退。前端将签发链接直接交给InAvatar，失败才退回姓名占位。字段策略、名单/计数与原授权均不变，验证真实SQL、字段隐藏与FULL、OSS序列化及浏览快照透传。
