# 需求：租户角色工作区

## 场景

组织管理员选中一个角色后，分页查看当前有效成员和被分配该角色的用户组。打开成员后，分页查看仍可修改或撤销的分配来源。

## 业务规则

- 只统计当前组织、目标角色、启用角色、生效中且位于时间窗内的分配。
- 成员页是直接分配与用户组继承的并集，按成员去重。
- 用户组继承包含显式组成员，以及按部门规则展开的成员。含下级时展开子部门。
- 用户组页只返回被直接分配该角色的可见用户组，不把继承成员回写成组。
- 治理读取沿用分配对象可见范围。受限管理员只看本人委派产生的分配。
- 无用户组读取资格或范围受限时，组页和组继承按可见组过滤，并标记 `inheritedSourcesRestricted`。
- 不接受 `revisionId`。响应中的版本号列表为空。
- 来源行仍走分配详情，有效状态与现有授权记录一致。

## 验收

- 成员、用户组、来源分别分页，SQL 按关系过滤，不先查 ID 再回表拼页。
- 同一成员的多条来源在成员页只出现一次，来源数等于可见有效分配数。
- 部门加人后，含下级的组继承能在后续查询中出现。
- 旧版本入口保持退出，不把版本参数解释进新接口。

## 字段权限

本变更覆盖 `20261014-iam-tenant-live-authorization` 中「当前角色不接受字段权限」的约定。租户角色和平台共享角色与平台自有角色使用同一套字段配置，差别是生效方式。

- 角色快照是该角色授予的字段上限。多来源取并集，不能超过资源声明。
- 成员资源：字段策略只在这个上限内再收紧。拥有者覆盖保持现状。
- 其他业务资源：只读当前角色快照。
- 旧的空快照：成员资源维持现有策略结果；业务资源按资源默认值。角色再次保存后写入明确快照。
- 通讯录资源不进入角色字段快照，求值仍走现有策略。
- 保存覆盖当前快照并立即生效，不产生业务版本。
