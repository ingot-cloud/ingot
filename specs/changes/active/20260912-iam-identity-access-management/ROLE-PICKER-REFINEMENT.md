# 平台角色单选树增量（2026-09-29）

状态：validating（开发完成，待用户手动验收）。批准依据：jy 确认单选角色版本，并明确要求实施本会话的“角色”单选树形弹窗计划。

## 需求与设计

平台角色分配字段改为“角色”。弹窗为单栏两级树：角色名称 → 已发布版本；父节点只展开，叶节点单选，不默认最新版。搜索在弹窗内按角色名称进行，300ms 防抖；确定后才更新草稿，取消保留原值。编辑已保存的分配仍不可更换角色。所有已选成员和用户组共享一个版本；确认同一版本保留范围参数，更换版本清理参数及预览。

角色及版本分别服务端分页，默认 20；展开角色才查询版本，版本倒序且可加载更多。不以展示名称分组，不拉取全集。少量已选节点按 ID 回显，关闭、依据和权限变化后失效缓存，迟到响应不得覆盖当前选择。

## 公共接口与兼容性

新增 GET `/v1/platform/assignments/role-candidates`（外部 `/api/iam` 前缀），参数 `delegationGrantId?`、`roleId?`、`keyword?`、`ids?`、`page=1`、`pageSize=20`。不传 roleId 查询角色根节点，传入后查询该角色的可分配版本。ids 只回显当前层少量节点，不能绕过准入与单条委派过滤。

响应 `AuthorizationRoleCandidatePage(items,total,page,pageSize)`；节点 `AuthorizationRoleNode(id,roleId,roleName,name,nodeType,revisionNumber?,roleRevisionRef?)`，nodeType 为 ROLE/REVISION。根节点仅包含至少一个可分配版本的启用平台角色；叶节点按版本号倒序、ID 倒序。树查询仅提供最小元数据，确认时通过现有 ROLE_REVISION 候选按一个版本 ID 取得完整参数。

准入与现有分配候选一致：可信平台身份、分配读取入口及直接创建/调整资格，或所选有效且归属于本人的委派；角色和版本必须符合该委派固定版本白名单。不调用通用角色列表，不授予额外治理资格。提交、预览契约保持原样，不变更表结构。

4. 选择旧版本后关闭再打开；根角色/版本不在第一页时仅按少量 ID 回显，仍保留选中状态，不拉取全集。
