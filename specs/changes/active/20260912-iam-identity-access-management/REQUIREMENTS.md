# Requirements

## 用户场景

- 平台人员创建组织、指定所有者并显式开通应用，不复制整套角色和权限。
- 组织管理员使用共享“成员查看员”角色，指定研发部及下级，使用户只查看授权成员且手机号脱敏。
- 租户在固定平台版本上移除编辑或替换范围，仅存差异；平台更新需确认升级才影响既有授权。
- 所有者指定受限授权管理员，由其给限定人员分配指定角色、范围和期限。
- 普通成员浏览通讯录，管理员独立设置组织可见性与字段规则。
- 运维迁移旧数据，明确映射自动转换，歧义授权经处置后才正式切换。
- 前端 Agent 仅读取本 change 即可理解菜单归类、页面状态、API 与验收。

## 业务规则

### R01 管理域和身份

平台域与租户域隔离。平台租户管理权不穿透租户业务。组织所有者有治理及授权管理权，但新业务应用需显式业务授权。允许所有者自授权并审计，不实现双人审批制度。

账号是全局登录主体，成员是组织内身份。移出组织不删除账号、不影响其他组织。租户成员编辑接口不修改全局登录手机号、密码及其他组织资料。

### R02 应用与资源

应用显式开通，基础应用在组织创建时初始化，其余通过平台或套餐开通。有效访问同时满足应用启用、开通有效、租户未停用及成员可用范围。开通本身不赋予业务操作权。普通配置不能关闭所有者必要的治理入口。

资源声明合法范围和字段能力，执行逻辑由服务端注册。操作为明确 ACTION；权限分组与菜单不隐式授权。“全选”仅当前操作，未来操作不自动授予。查看覆盖列表及详情，编辑、导出不隐含查看。

### R03 共享定义与最小初始化

系统治理角色统一维护且不可租户定制。共享业务角色发布不可变版本。直接使用只保存授权引用；按需定制保存基础版本引用和差异；未使用不创建租户角色记录。

差异支持新增、移除操作、替换操作范围及必要元数据覆盖。移除只影响该角色，不是用户全局拒绝。租户差异不得多层继承。平台更新不覆盖旧版本；升级必须三方预览、解决冲突、选择授权记录重新校验。

新组织仅保存组织、所有者成员、根部门及关系、治理授权、应用开通和必要设置或默认策略版本引用，不复制角色、资源、菜单、权限及默认策略条目，不生成空组和空差异。

### R04 授权与数据范围

角色逐操作定义范围规则，授权记录引用角色版本、填写参数及期限。范围包括域内全部、资源定义的本人、所属部门、指定管理部门及资源支持的指定对象。所属部门随任职变化；指定管理范围不随任职变化。包含下级必须明确。

各授权独立计算功能及范围后再合并，禁止跨角色拼接。创建验证新归属，修改验证原对象及新归属。读、统计、详情、导出在数据库层过滤。

多部门成员查看及组织基本资料编辑按任一授权部门匹配；暂停、恢复、移出须覆盖全部部门关系。无部门成员不匹配部门范围。调整部门校验变更两端；移动部门校验子树与新父节点；非空部门不能删除。批量写全部通过才执行。

### R05 静态用户组与受限委派

用户组只表达人员集合，可包含成员、部门引用及是否包含下级，不嵌套；部门人员变化实时影响有效集合。用户组本身不授予权限。

委派独立于业务操作权，限定角色版本、接收人员、逐操作范围上限、有效期及最长分配期限。受限管理员不能创建角色或继续委派；不得拼接多条委派的不同维度。

派生授权受来源委派持续限制。变更用户组、部门、委派及角色版本不能间接扩权；组编辑必须校验其授权引用影响。

### R06 通讯录与字段

普通通讯录与后台成员管理使用独立入口，前者可见不意味着后者可管理。默认全组织基础信息可见，手机号和邮箱脱敏。

通讯录没有匹配允许规则时使用默认；有匹配允许规则则以其目标并集替代默认；最终扣除禁止范围，本人基础资料始终可见。祖先导航不开放其他数据或隐藏人数。搜索、详情、选择器、计数一致。

字段按场景、查看者、目标范围设置隐藏/脱敏/完整及可编辑。无匹配用默认，多条匹配取更严格，平台强制约束取最终上限。编辑需完整展示、字段允许、操作及对象范围同时满足。服务端处理所有响应与导出；受限原值不能通过搜索/排序/筛选推断。

### R07 诊断、审计和失效

诊断解释真实引擎结果，显示来源及限制，不执行目标操作、不模拟登录。诊断权限限制查看者可查询的成员及对象，不泄露范围外信息。

授权写记录操作者、管理域、对象、前后差异、版本、关联委派/授权和时间。敏感原值不写入审计。角色停用、成员退出、组变更等触发失效；快照最长 30 秒并受期限边界限制。关键授权写入检查最新状态，不以缓存放行撤销的委派。

### R08 迁移与独立上线

保留可迁移数据但不保留旧接口及越权行为。旧库只读、新库导入、停写切换；不双写。模糊权限不自动扩大，所有切换阻塞项有明确处理记录。迁移不复活删除数据，不迁移在线会话和旧授权缓存。

## 边界与非目标

- 本仓库不实现前端页面，但须给出完整行为契约，正式切流依赖前端联调。
- 认证协议留在 Auth，安全能力留在既有服务；辅助字典、发号暂留 IAM，不另拆服务。
- 不新增其他业务系统、不合并 Member、不构建通用 SQL/策略脚本编辑器。
- 不迁就旧 endpoint、旧角色码短路、动态通配及默认开放行为。
- SQL 规模优化不是本次前置条件，先完成标准范围和关联归属的正确执行。
