## 需求与设计

应用目录内平台/组织应用的菜单维护及应用创建草稿共用三组配置：基本信息、访问控制、高级配置。创建使用全屏 pinned 三步，详情使用只读 Tab，编辑从当前分组进入并可直接保存；校验所有分组并定位错误，取消/成功返回原详情 Tab。未保存离开需确认，失败保留草稿，409 阻止重复提交并提供重新加载。应用向导内保存菜单只更新草稿，仍通过整包一次提交。

新增 hidden/isCache/props（默认 false）、routeParams（有序 {name,remark?}，默认 []）；配置响应增加只读 resolvedPath。配置 path 为基础路径，bootstrap path 为完整模板。创建遗漏取默认；更新遗漏保留旧值；明确关闭 props 清空参数。第一版参数必填、字符串、无默认值/正则，名称符合 [A-Za-z_][A-Za-z0-9_]* 且不重复；基础路径不混入动态占位符，尾斜杠归一化。带参页面必须隐藏；目录只有导航配置，保存归一化为 OPEN/ANY/无关联操作、无页面缓存和参数。受保护页至少关联本应用操作，父节点不能成环。

隐藏只移除侧栏、搜索和默认入口，不移除授权路由。剪除空导航目录；隐藏页高亮最近可导航祖先，否则保留本应用最近选中项/使用应用入口。面包屑使用实际参数且当前页不可点击。路由名为空使用 iam-menu-{id}，显式名称保持；路径/名称冲突检测保留。菜单保存后主动 bootstrap 并替换已注册动态路由；其他会话下次 bootstrap/登录生效，无实时广播。

admin-core 共用路由渲染器覆盖根、主内容和简单布局，稳定包装组件按路由身份及模板顺序的路径参数缓存，查询/hash 不增加实例；中间布局保持子页面缓存。每容器 LRU 上限命名常量 20，目录无开关。身份/改密/授权/路由配置变化清缓存，相同 bootstrap 不清缓存，关闭缓存页面正常销毁。

数据库新增布尔及参数 JSON 列；权威 DDL、生成初始化 SQL、OpenAPI 和前端副本同步。存量路径不自动改写，已有库使用增量脚本保留数据；完整重建文件不得用于升级。前后端共用相同参数/类型/准入校验规则。旧调用方省略新字段兼容；目录切换时清理不适用设置。新增公共契约遵循 JavaDoc、命名常量、构造注入及前端共享包边界。

## API

现有 MenuDraft、ApplicationBundleMenu、MenuRecord 增加 hidden、isCache、props、routeParams；请求布尔值可空用于保留更新语义，响应归一化。MenuRecord.resolvedPath 只读。MenuNode 增加三个布尔值，其 path 为服务端生成的模板。无需新增业务端点。参数备注仅用于配置回显，不作为运行时参数值。

## 宪章符合性

公共无页面逻辑放 admin-core/admin-common；页面实现放 platform 插件，不增加插件互依，不改变技术栈与主题边界。全部任务限定本菜单能力，使用当前身份与原授权规则。

## 缓存失效与编辑流程协同

路由配置变化立即移除缓存条目并销毁失活实例。当前活跃页面继续作为普通页面显示，离开后销毁，避免菜单保存时中断详情抽屉；下一次导航使用已替换的路由。若当前菜单已不在授权路由中，立即重新匹配并退出该页面。身份、退出、强制改密及授权版本变化仍立即销毁包括活跃页面在内的实例。这是同时满足缓存失效和保存返回原详情 Tab 的实现约束。
