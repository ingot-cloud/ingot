# 数据迁移与切换

## 1. 原则与输入

目标是保留可确定的数据与合法授权，不保留旧接口、超管跨域绕过或未执行范围导致的过大访问。采用只读源快照、独立新库；默认不写源库，不自动发现并连接生产数据库。

输入包含实际数据库一致快照、schema/version 指纹、关联服务配置清单、操作映射表、所有者映射、歧义处置文件。仓库 databases/ingot_core.sql 仅用于结构和夹具，不视为最新生产数据。敏感凭证不进入日志/报告。

工具命令职责为 preflight、dry-run、import、verify、report；每次带 batchId、源指纹、目标标识、规则版本。导入幂等，旧新 ID 映射唯一；源变化不能复用同一批次。工具仅执行显式配置的目标库，不提供默认覆盖旧库的操作。

## 2. 映射表

| 旧数据 | 新去向/转换 |
|---|---|
| sys_user | Account，保留可用 ID、摘要和安全状态；组织资料初始化自有明确来源，不把新成员字段写回全局 |
| sys_user_tenant | TenantMember；唯一 account+tenant，保存旧关系→memberId 映射；该表 name/avatar 是组织信息，不误作成员姓名头像 |
| sys_tenant | Tenant；验证所有者资料，缺失则使用显式映射，不把所有 org_admin 都升为 owner |
| tenant_dept / tenant_user_dept_private | Department / MemberDepartment，保留可用 ID，多部门、主部门验证 |
| platform_app / resource / permission / menu | 目标目录及操作映射；菜单与操作独立，不能从 path 自动推导新权限 |
| tenant_app_config、默认开放事实、套餐 | 明确开通记录、来源和期限；无覆盖且旧实际开放的应用在快照时转显式开通，明确禁用保留 |
| platform_role / role_permission | 对应平台域角色或共享租户角色版本；分组仅展示；系统治理角色由新定义建立 |
| tenant_role_private | 自定义角色及版本；保留可追踪映射 |
| tenant_role_permission_private | 平台角色的租户追加转差异 ADD；自定义权限归入本地版本；与新基础重合项消除冗余 |
| platform/tenant_role_data_rule | 与对应操作共同映射，基础范围或差异替换；缺操作、空资源及矛盾规则进入异常 |
| tenant_role_user_private | Assignment；dept_id 转命名管理范围参数；空 dept 的旧语义须结合旧模型判断 |
| sys_user_social / sys_social_details | 社会化身份关联和配置；密钥/租户绑定验证，不能仅迁 ID 后视为可登录 |
| password_history / password_expiration / account_lock_state | 保留历史、到期和锁定状态；不能只依赖 sys_user.locked 冗余列 |
| 字典、套餐记录、biz_leaf_alloc | 维持辅助领域事实，逐表迁移并验证业务键/发号高水位不倒退 |
| security_event 等审计 | 保留原事实、旧标识和来源映射；不虚构新授权事件 |
| 已删除/停用记录 | 保留状态或进入有记录的归档去向，不复活 |
| 会话、令牌、授权快照/缓存 | 不迁移，新系统重新登录与重新计算 |

源库发现未列出的表时预检报告用途及保留方式，不能静默跳过。媒体文件引用需验证存储仍可访问；本次不自动搬迁对象存储。

## 3. 权限与歧义处理

操作映射显式记录旧 ID/code 到新 ACTION，支持旧粗权限拆分但须评审拆分后的能力；不能根据字符串相似或角色名称自动授予。通配符按源快照有效具体目录展开，不包括未来新 ACTION。

旧多角色合并先识别合法来源；不能把跨角色拼出的 ALL 视为目标必需能力。规则明确则保留，有以下情况列阻塞项：
- 无法对应操作/资源、数据范围不明确或引用缺失。
- 账号/成员跨租户引用、重复业务键、部门循环/孤儿。
- 多候选所有者或没有可靠所有权。
- 旧超管/组织管理员隐式能力无法拆分为新治理与业务角色。
- 凭证格式或社会化配置不可验证。
- 新旧范围语义无法证明等价。

每项处置记录 KEEP_MAPPED、NARROW、RECONFIGURE、ARCHIVE 或 SKIP，并附理由、操作者和关联映射；影响授权/数据的收窄或放弃不能由工具默默决定。待确认授权不启用；影响正式切换的清单必须处置完毕。

不必为了保留旧业务能力复制平台角色：固定共享版本加最小租户差异即可。旧角色无法合理共享的独立迁入自定义，不强行合并不同业务意图。

## 4. 验证与报告

先验证表级数量、状态、业务键、关联、引用与映射完整性。数量变化须有明确转换解释，例如 account+tenant 去重，不能仅比较总行数。

按主体+操作比较新旧合法授权：PRESERVED、NARROWED、EXPANDED、UNRESOLVED，范围无法证明包含关系时使用 UNRESOLVED。部门/对象集合可精确比较；不能以几个查询样例代替授权等价证明。EXPANDED 需显式批准处置，不能以修复目录缺失为由自动放行。

在隔离演练环境验证账号登录、成员状态、跨组织切换、角色版本/差异、只读研发、委派、字段及导出。密码只验证摘要格式和受控测试账号登录，不能索取全部用户明文；不兼容摘要列入处置。

工具报告不得含密码摘要、令牌、私钥及不必要的联系方式原值。发号和 ID 保留通过碰撞及高水位检查。失败批次不得标记 verified，未完整验证不能放行切换。

## 5. 切换与回滚

1. 只读预检和试运行，准备隔离目标库。
2. 完成全部映射、歧义处置及至少一次全量演练。
3. 后端与前端契约联调、端到端验收完成。
4. 停止旧系统业务写入和相关后台写任务，获取最终一致快照。
5. 最终导入、结构/权限/关键流程验证；失效旧会话与缓存，启用新路由前确认环境隔离。
6. 新系统先在未开放业务写入条件下验收，再开放业务写入。
7. 保留源库备份、规则版本、批次报告和切换记录。

只在新系统尚未接受业务写入的窗口允许切回旧系统。开放写入后禁止直接切回丢弃新数据；采用前向修复，若必须回退，先制定并确认反向数据处理方案。本 change 不实现双写、CDC 或通用反向迁移。

实际源快照、停写时间及环境凭证为执行时输入，不由 Spec 编造；缺少输入阻止执行迁移，但不阻止先开发工具和夹具测试。
