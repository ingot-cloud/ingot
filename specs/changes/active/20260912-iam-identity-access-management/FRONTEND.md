# 前端页面与交互规格

> 本文件是后续前端 Agent 的输入；本仓库不实现页面。与 API、DESIGN 一并读取，遵守前端仓库自身 SDD 及架构规范。参考已观察的飞书分步配置、部门选择、只读详情和预览方式，不声称复刻飞书内部算法或商业版本限制。

## 0. 双入口登录与身份选择（2026-09-19：已有部分实现，完整联调待验收）

权威接口与完整状态机见 [BFF-LOGIN](./BFF-LOGIN.md)。两套独立登录应用，BFF 路径固定 domain，浏览器只提交业务字段，不传 domain/OAuth 参数。平台入口不展示租户候选，无平台成员失败不降级；租户入口只使用租户成员资格，零候选失败，单候选由 BFF 自动完整认证，多候选选择后重验。临时事务不能请求 bootstrap。

前端当前按其 DESIGN 第8节使用 apps/admin、apps/admin-platform 两个独立宿主并复用公共包及业务插件，分别部署到两个 origin；两登录站独立托管，四站同主域 HTTPS。双身份可同时在线、会话独立；普通退出一域不影响另一域。跨域必须在另一登录站重新认证，不复用已有 Auth 会话。

Admin 同源 BFF 建立浏览器绑定事务；不向 BFF 传 returnTo 或任何重定向 URL。登录页只持有事务 ID。READY 表示可交接，不代表登录站获得业务会话；目标 admin 完成页消费一次性 ticket 后建立 host-only Cookie，再 bootstrap 并核对预期 domain。BFF 落地页为注册 defaultReturnTo；深链仅管理台同源 sessionStorage 的相对 path。直接访问登录站只能跳构建期配对的 admin `/auth/start`。401/登出只进本站 `/auth/start`，不信任 redirect_uri query。

平台 tenantId=null，兼容内部 DTO 时 allows=[]；有效平台身份无菜单显示已登录无功能，不强制选租户或循环登录。平台管理租户列表只管理实体，不是业务身份切换源。切租户重新认证，新会话成功生效后清菜单、查询、详情、表单并忽略旧响应；取消或失败保留原会话。其他同源标签页察觉上下文变更时清理旧视图，另一域不受影响。

复用挑战、HYBRID、凭证检查、锁定、初始改密，Member 不变；仅静态展示的二维码登录入口隐藏，不在本轮实现扫码。登录页面/组件进入独立 auth 插件，无页面逻辑进入 auth 公共包，禁止 App 引用另一个 App 源码。全部 IAM 页面按以下逐页契约完成，不以旧前端任务勾选代替验收。

## 1. 导航与架构

两份管理台部署分别明确显示平台/当前组织身份；租户切换重新认证，新会话生效后清除旧菜单、资料、查询缓存和请求，忽略迟到响应。

同一登录账号可拥有平台及多个组织身份。平台人员、平台组在“平台管理”下维护；平台组只选择平台成员，不展示租户部门。成员状态操作只作用于对应身份，全局账号禁用另属账号安全操作。

平台最多四个一级目录：

| 一级 | 二级及 Tab |
|---|---|
| 组织与租户 | 租户管理；详情 Tab：基础信息、应用开通、所有者、状态记录 |
| 应用与配置 | 应用目录、套餐、共享角色、字典；应用详情 Tab：基本信息、资源与操作、菜单 |
| 平台管理 | 平台人员、角色与授权；后者 Tab：角色、授权记录、授权管理员 |
| 安全与运维 | 现有安全策略、会话、事件与审计、运维能力；不新增未经后端支持的空功能 |

租户最多四个一级目录：

| 一级 | 二级及 Tab |
|---|---|
| 组织管理 | 成员与部门、用户组、组织设置 |
| 权限与应用 | 角色与授权（角色/授权记录/授权管理员 Tab）、应用管理 |
| 安全与合规 | 成员权限（通讯录可见范围/字段权限 Tab）、现有安全设置、审计 |
| 工作台 | 已授权业务应用入口、普通通讯录 |

诊断在角色与授权页工具入口及成员详情快捷入口，不独立一级菜单。资源、操作、范围、版本均放详情。无可见子页时隐藏父目录；跨页链接亦验证目标能力。

沿用 Vue 3、Element Plus、现有详情抽屉、主题 Token。业务页面放相应 plugin，通用选择器、范围编辑、权限展示进入公共包，插件不互相依赖。导航不按微服务或数据库表划分。

## 2. 页面交互

本节使用 UI 编号标识页面，验收编号 F01–F09 见 ACCEPTANCE。

### UI01 租户管理

列表按状态及名称筛选。所有者列展示成员显示名，缺失时回退成员 ID。创建使用全页向导：组织资料 → 指定所有者 → 基础应用/套餐 → 预览并提交。展示将创建的最小实体及开通结果，不出现“复制角色模板”选项。不向管理员泄露账号是否属于其他组织。

详情默认只读。应用开通修改显式展示开始/结束、来源、禁用及过期结果；套餐变化不自动应用。停用展示影响并确认；平台页面无“进入租户业务”入口。

### UI02 应用与配置

列表按名称、状态及是否组织默认（baseline）筛选。组织默认应用在名称旁展示「组织默认」标签。资源和操作在应用详情内联合展示。操作区分查看、编辑、导出、移出等，不用“管理”复选项包办全部。范围候选从资源能力接口读取。菜单配置独立引用进入页面 ACTION，可选择 ANY/ALL，不创建按钮菜单。

字典及现有安全页面沿用各自领域功能，只更新身份及授权接入。未实现的能力不以空按钮占位。

### UI03 成员与部门

左侧部门树、右侧成员表。姓名/头像打开只读详情，基本资料、部门关系、授权信息分区。拥有相应操作才出现编辑、调部门、暂停、恢复、移出、导出。导出先 POST `/v1/tenant/members/export` 取得任务 id，再轮询 GET `/v1/tenant/members/export/{id}/status`：`PENDING`/`RUNNING` 继续等待；`SUCCEEDED` 后再 GET 下载。`FAILED`/`EXPIRED` 或 404 按对象不可访问处理，不得把下载 503 当成成功空表。状态接口不返回成员快照，也不能用第一页列表冒充导出。

只读角色看到正常描述内容，不用 disabled 输入框冒充详情。编辑时隐藏或脱敏字段不进入表单。保存仅提交修改且可编辑字段；授权变更不能使旧表单提交受限字段。

多部门成员显示可见部门关系；无权操作的对象按钮按后端 capabilities 禁用并显示原因，不自行用部门数组判断权限。组织移出明确说明不删除全局账号。非空部门删除与子树移动由服务端返回具体限制。

### UI04 用户组

列表展示名称、有效人数（有权范围内）和用途。详情 Tab：成员来源、有效成员、引用位置。成员来源可以直接选人或选部门，部门旁有“包含下级”开关；有效成员去重显示来源。

修改前调用 preview，列出受影响角色授权、应用和策略；越权阻止提交。删除被引用组说明引用位置，不静默级联撤权。无权知道具体引用时只显示受限摘要。

### UI05 角色目录与编辑

目录筛选系统治理、平台共享、租户定制、自定义；显示当前版本、使用版本和状态。共享只读，操作为“分配使用”“基于此角色定制”。系统治理无定制按钮。

创建/定制全页步骤：
1. 基本信息：名称、说明、分组、基础共享版本（若定制）。
2. 功能选择：应用 → 资源 → 具体操作；提供“仅选查看”和当前项全选。
3. 范围：只展示选中操作；显示“本人所属部门”和“授权时指定管理部门”区别；包含下级独立开关；支持复用命名参数。
4. 预览：自然语言展示最终能力、参数、版本及影响，完整校验后发布。

定制有“最终生效内容”“本组织调整”两种视图，标签为“来自平台”“本组织新增”“本组织移除”“范围已调整”。恢复平台设置删除差异。移除文案说明仅本角色不授予，不宣称此人全局禁止。

无依赖隐含勾选。编辑无查看时提示可能无法进入页面，允许管理员明确选择是否补充查看。新版本发布不自动升级授权；详情允许追踪旧版本。

### UI06 共享版本升级

选择新基础版本 → 三方差异 → 解决冲突 → 预览最终定义 → 选择升级授权记录 → 提交。默认不选择既有授权。未处理冲突禁用提交；操作删除/范围改变不静默取新旧其中一个。展示不兼容的委派来源，须先更新其允许版本后再升级派生授权。

保存出现 409 保留解决草稿并重新比较，不直接覆盖。后台不能通过发布共享版本即时扩展所有租户权限。

### UI07 授权分配

大抽屉步骤：人员/用户组 → 角色版本 → 范围参数与有效期 → 效果预览。受限管理员只列可分配版本，候选人员和管理对象也受其委派限制。

所属部门按每个接收者展开预览；指定管理部门不随接收者任职变化，旁边解释。多个操作复用参数显示引用清单。不可用应用的角色项标记原因，不提交无效授权。

列表显示直接/组来源、角色版本、范围摘要、期限、委派来源。撤销有影响确认。批量提交中任一项无效均不保存，逐项展示错误。

### UI08 授权管理员

配置管理员、角色版本白名单、接收对象、逐操作范围上限和期限。明确“允许给别人授权，不自动获得业务操作权”。无二次委派或角色创建开关。

收缩/撤销先展示派生授权影响。与角色发布无隐式联动，新角色版本必须显式加入白名单。此页自身由治理权限控制。

### UI09 应用可用范围

只配置平台已开通应用的人群和租户开关，显示平台开通期限。说明“应用可用不等于拥有其中的业务操作”。所有者治理基础入口不可被普通配置关闭。

### UI10 通讯录与字段

通讯录先默认规则，再允许/禁止规则。句式：“哪些成员，可以/不可以，看到哪些部门或成员”。选择预览成员后显示真实可见树与成员样例、匹配原因，必要路径用导航骨架样式，不显示隐藏分支统计。

字段页先选场景、查看者、目标范围，再字段矩阵：隐藏/脱敏/完整、可编辑。非完整不能开启编辑；完整也不自动授予更新操作。右侧样例使用服务端预览的脱敏数据。多规则严格取值及平台上限明确解释。

### UI11 权限诊断与审计

诊断输入成员、应用、操作、可选目标。输出结论、应用状态、直接/组授权、角色版本、委派、范围与字段限制。提供有权配置的跳转，不提供“模拟执行”或登录按钮。

审计按操作者、对象、类型、时间筛选，详情展示安全前后差异和来源链。当前未发布独立审计导出端点，不提供可操作导出按钮；未来若增加，须有独立操作权限且不能含凭证或被隐藏的字段原值。

### UI12 普通通讯录与工作台

与后台成员管理调用不同 API，通讯录列表与部门树必须携带 `purpose=DIRECTORY`，不能改成管理用途以换取全集。只有通讯录权限也可浏览，但没有后台编辑入口。搜索、人数、列表和详情均消费服务端结果。业务应用入口同时受开通、人群和页面操作约束。

## 3. 通用交互与状态

| 状态 | 页面行为 |
|---|---|
| 无 ACTION | 隐藏菜单/操作，不加载无权详情 |
| 有 ACTION 但对象越界 | 对正常可见对象禁用操作，展示后端 reason，不暴露隐藏目标 |
| 业务状态不允许 | 展示业务原因，例如部门非空 |
| 提交中 | 防重复提交；批量事务失败不误提示部分成功 |
| 未保存离开 | 关闭、Esc、切 Tab/路由提醒丢弃；取消留在原处 |
| 409 | 保留草稿，刷新差异后重试 |
| 撤权/403 | 刷新能力与菜单，关闭不可见详情；保留本地输入供查看/复制但禁用提交 |
| 503 | 重试状态、阻止受保护操作；不当成成功空列表、不登出、不把旧数据视为最新 |
| 404 | “不存在或不可访问”，不区分真实存在 |
| 空范围 | 已确认有功能且查询成功时显示“当前范围内暂无数据” |
| 切换身份 | 清缓存、详情和路由，忽略旧响应，重新 bootstrap |

角色名不能用于前端放行。使用响应式能力，不只在 mounted 时移除 DOM。对象能力随列表批量返回，无每行一次权限查询。授权到期后使用前刷新，403、窗口重获焦点及身份切换触发更新；前端永远不是最终安全边界。

## 4. 前端交付与联调

前端 Agent 继续维护现有 20260913-base-iam-admin change，不创建重复 change；保持四个一级目录及以上业务语义。API 未实现时可按本契约创建测试夹具，但不能自行决定权限合并、身份选择或接口省略。2026-09-16 T13 已重发 96 路径 / 161 操作 OpenAPI，覆盖账号、本人资料、辅助入口、purpose 与导出轮询；仍不是 A24 真实 HTTP 验收，联调前以该快照与控制器行为为准，不得沿用 77/132 旧快照。

实现前校对后端已验证 OpenAPI；每个页面需覆盖只读、范围受限、字段限制、编辑离开、冲突、撤权、503 和跨组织切换。验收编号见 ACCEPTANCE 的 F 系列。前端任务不在本仓库标记为已实施。

## 5. 统一页面样式与交互（2026-09-19，后续开发验收约束）

本节在前端 INTERACTIONS 中保持权威副本。参考前端仓库 `plugins/org/src/pages/contacts/user/`、`contacts/dept/` 的列表、详情、action组织方式，并遵循其in-coding-standards；参考的是交互模式，不复制旧PMS身份语义、空操作或旧接口。新IAM页面和此前已接页面都必须对齐。

### 5.1 布局、视觉与动作

- 复用 InPageFrame/InPageHeader、InSplitLayout、InTable、InTableActions、InDetailDrawer/InDescriptionList及现有编辑会话组件。列表密度、工具栏位置、标题/计数、右侧操作列、列设置和分页保持一致；树表双栏沿用通讯录模式，不为每个IAM域另搭布局。
- 工具栏与行内操作统一使用类型化action配置；按业务重要性配置主操作、快捷操作、更多菜单与危险操作，不散落同义按钮。搜索筛选在tools-start，工具栏动作在tools-end；无业务依据不照搬旧页面的导入/创建占位。
- 没有ACTION隐藏动作；可见对象但范围/状态受限时禁用并展示后端原因。动作响应能力刷新；姓名/头像详情链接同样受详情权限约束。危险变更明确说明对象和影响并确认，提交中防重复。
- 名称/头像打开正常只读详情，编辑通过独立入口进入；不以禁用输入框替代只读详情。简单编辑用现有抽屉，角色/升级用已约定全页向导，分配用大抽屉；页脚取消/保存位置及loading一致。
- 色彩、边框、字号、间距与图标使用现有主题Token和UnoCSS，适配现有主题与窄屏；不硬编码另一套品牌色。状态标签、时间/空值格式和空态/错误/不可用反馈统一，禁止把内部JSON或裸ID输入当最终业务交互。

### 5.2 搜索、筛选与选择器

- 主搜索无label、带搜索图标与明确placeholder，回车或清空执行查询；不另加主搜索按钮。统一页码重置及请求状态。
- 工具栏枚举筛选用InPicker，首项“全部”、空值不传条件，切换即查。主搜索之外条件不超过2个可直出；达到3个或有远程实体筛选时，只保留至多1个高频筛选，其余进入InFilterPanel，显示额外生效条件数和重置入口。
- 表单选择沿用InSelect/远程实体选择器；InPicker不替代表单。人员、部门、应用、角色版本及所有者选择受服务端purpose/范围限制，支持远程分页与检索，不能只加载首200条或让用户填写裸ID。旧选中项越权后不得从全员接口补回。
- 搜索、排序、筛选遵循字段权限和服务端契约，不在前端从隐藏原值重做检索；普通通讯录与后台管理保持不同purpose。

### 5.3 草稿、反馈与功能完整性

- 抽屉关闭、Esc、切Tab或路由离开遇到未保存修改时确认；取消离开保留草稿。409保留草稿并刷新版本/差异，403刷新能力且禁用越权提交，503明确不可用与重试，404不泄露对象存在性。
- 主体、角色版本、范围、期限、字段/规则等草稿变化立即失效旧preview；异步预览只接收当前draftRevision/contextEpoch结果。保存不能复用过时预览，服务端仍须重新鉴权。
- 修改表单仅提交可编辑且实际变更字段，不提交MASKED占位或HIDDEN值；成功刷新相关列表/详情/能力，失败不报成功、不自动重复mutation。
- 列表、详情、创建/编辑、停用/删除、预览/发布/升级、授权/撤销等按该资源真实契约完成。未知DTO、JSON展示、空handle函数只能标为部分实现；未发布的功能不显示可操作按钮，不用Mock补成“完成”。
