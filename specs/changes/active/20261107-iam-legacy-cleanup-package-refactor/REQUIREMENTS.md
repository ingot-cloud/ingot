# Requirements

## 用户场景

维护者能够直接定位 IAM 有效用例、内部规则、持久化与接口契约，业务不再依赖历史用户/组织模型。调用服务只依赖必要的 Java 契约，类名准确表达账号、成员、身份、目录应用和角色版本应用等语义。

## 业务规则

1. 删除前先替换唯一有效消费者；检查 Java、Mapper XML、自动配置、Bean 名、序列化、测试及生成工具。
2. API 不保存持久化实体、Mapper、业务内部 BO 或 MapStruct 转换器。保留 RPC、必要字段依赖及消费端在线授权装配。
3. commons 仅保留有真实共享用途的契约及其传递依赖；IAM 专用模型迁入 provider。
4. 保留类也必须审查命名；职责混合先拆分再命名。不将历史阶段名 Live、模糊 Biz/Support/Editor 直接沿用到新职责。
5. 正式 HTTP/RPC 路径、方法、JSON 字段、稳定枚举字面量、错误、权限、事务、分页及时间/OSS语义保持。Java 源码与二进制兼容不作承诺，消费者同批重建。
6. 历史表、数据、数据库升级脚本不变。Java 历史迁移分析器退出运行模块，已有离线迁移工具及历史记录保留。

## 验收标准

- [x] A01 旧实体、服务、Mapper/XML、转换器和扫描引用按清单退出，无维持编译的空壳。
- [x] A02 API 无 BaseModel、实体、Mapper、MapStruct；公共枚举允许最小 MyBatis 注解依赖。
- [x] A03 provider 依赖方向和命名清单通过自动检查；接口不直接调用 Mapper。
- [x] A04 正式接口可达 Schema、序列化夹具和 RPC 消费者回归通过；仅无调用的旧 Schema允许退出。
- [x] A05 登录、当前身份、社交绑定、字典、发号、成员部门、角色分配、委派、字段、表格、版本应用回归通过。
- [x] A06 平台/租户隔离、fresh 写入、失败关闭、审计、提交后失效及 worker 租约回归通过。
- [x] A07 Spring/Feign/MyBatis/Jackson 装配、缓存兼容及跨节点通知验证通过。
- [x] A08 数据库文件无变更，生成检查无数据库漂移。
- [ ] A09 真实环境及用户验收证据完成后更新 current，再归档；开发测试不替代产品验收。

A01–A08勾选表示本轮限定自动化与隔离环境证据完成，详细命令和已知无关失败见VALIDATION；不代表A09目标环境/人工验收已经完成。
