# 合并查询与七天缓存对照

## 可取得的调用频次

本机 IAM Sentinel 指标 200 个非索引文件，覆盖 2026-09-14 至 2026-11-09（本机时间），共 15,746 个有记录的秒。按进程、秒和路由对重复记录去重，再汇总同一秒的通过请求数。Sentinel 日志按活跃区间写入；「平时」以该路由有请求的秒统计中位数和 P95，峰值另列。峰值分钟为完整自然分钟的请求数除以 60。

| IAM 入口 | 通过请求 | 活跃秒 P50 / P95 | 单秒峰值 QPS | 峰值自然分钟平均 QPS |
|---|---:|---:|---:|---:|
| `GET /v1/me/bootstrap` | 1,011 | 1 / 1 | 3 | 0.183 |
| 平台 `action-catalog` | 17 | 1 / 1 | 1 | 0.017 |
| 租户 `action-catalog` | 13 | 1 / 1 | 1 | 0.033 |

这是开发环境的历史日志。路由指标没有应用 ID 或目录版本，无法估算目标环境的每应用读写比、同版本复用和真实命中率。当前工作区没有目标环境访问日志或指标导出。原始聚合：[local-sentinel.json](./evidence/local-sentinel.json)。

## 同首期基线复测

沿用首期的合成身份、请求和应用数据，每组串行预热 30 次、采样 200 次。表中首期目录使用直查对照；首期 Redis 热读的完整查询预算平台 / 租户为 7 / 16，本次无 Redis 亦达到相同预算。各轮本机调度不同，串行延迟只作记录，缓存判断采用下节同请求率对照。

| 场景 | 首期 → 本次 SELECT/请求 | 首期 → 本次 P95（ms） | 首期 → 本次 P99（ms） |
|---|---:|---:|---:|
| `普通成员 bootstrap，1 应用` | 20 → 17 | 14.33 → 14.45 | 15.60 → 17.04 |
| `普通成员 bootstrap，16 应用` | 20 → 17 | 13.29 → 16.10 | 15.94 → 19.47 |
| `委派管理员 bootstrap` | 17 → 14 | 10.63 → 10.07 | 12.42 → 11.09 |
| `租户拥有者 bootstrap` | 12 → 9 | 6.85 → 6.73 | 8.22 → 7.82 |
| `普通成员 capabilities，16 应用` | 13 → 13 | 8.50 → 9.71 | 10.09 → 10.55 |
| `平台 action-catalog` | 9 → 7 | 4.85 → 4.90 | 6.23 → 5.84 |
| `普通租户成员 action-catalog` | 18 → 16 | 10.15 → 10.14 | 12.41 → 11.00 |

有绑定时，菜单查询减少 3 条 SELECT；完整 bootstrap 的减少量与之吻合。双节点另验证同一菜单加上绑定前后整条接口查询预算相同，且绑定停用操作在 `ALL` 下仍限制准入。原始样本：[baseline-rerun.jsonl](./evidence/baseline-rerun.jsonl)。

## 等请求率实验口径

- 隔离 MySQL 8.4、Redis 8.2.0，使用 IAM MySQL HTTP 夹具的两个 Tomcat 节点。生产直查与实验候选共享数据库、连接池、真实 IAM 入口和鉴权服务；夹具用合成身份代替上游登录与网关。候选只替换目录读取，保留租户授权和菜单准入 SQL。
- 每个入口按固定到达间隔分别发送 20 QPS（8 秒，160 请求）和 100 QPS（6 秒，600 请求），对比组使用同一路由、身份、数据和请求率。相邻组交替顺序。预热后测热读，另在 100 QPS 下切换版本测量一次冷启动。HTTP 延迟从计划发送时刻计至收完响应，包含调度抖动；用采样内提交 QPS 验证对照成立。
- 操作目录样本每应用 32 或 512 个操作。菜单样本在初始化目录基础上分别增加 8、264 个页面，每页两条操作绑定。菜单缓存只保存结构；每次查当前应用版本、启用菜单、准入规则和绑定。操作目录缓存每次从数据库读取应用头和版本，按视图隔离内容。仅试验库新增版本列；缓存缺失查合并 SQL、确认版本仍相同后回填，实验键 TTL 为七天。
- MySQL `performance_schema` 统计查询耗时、语句 CPU、检查与返回行数；全局 `Bytes_sent` 差值包含少量采集流量。CPU 是 SELECT 线程执行时间，不是主机 CPU 百分比。本实验未采连接池等待和目标环境网络拓扑。热读结果来自反复访问相同版本，不能当作线上命中率。

## 等 QPS HTTP 实测

每格为直查 → 版本化 Redis 热读。两种实现热读 SELECT 数相同：夹具平台目录 7 条，租户拥有者目录和 bootstrap 9 条。24 组热读对照与 2 组版本切换共 10,120 次请求，HTTP 错误为 0。全部热读请求命中；两个版本切换窗口各有 499/500 命中，首次缺失回源后恢复。实测提交 QPS 为目标的 98.3%–100.0%。

| 入口 | 目标 QPS | P95（ms） | P99（ms） | MySQL SELECT CPU（ms/请求） | MySQL 发送字节变化 |
|---|---:|---:|---:|---:|---:|
| bootstrap，少量菜单 | 20 | 27.10 → 26.50 | 29.64 → 29.66 | 4.11 → 3.92 | -16% |
| bootstrap，少量菜单 | 100 | 11.39 → 9.70 | 14.29 → 12.41 | 1.61 → 1.44 | -16% |
| bootstrap，大菜单 | 20 | 28.68 → 33.78 | 34.04 → 53.87 | 5.94 → 6.00 | -33% |
| bootstrap，大菜单 | 100 | 13.49 → 13.59 | 15.24 → 15.83 | 2.99 → 2.71 | -33% |
| 平台目录，32 操作 | 20 | 20.18 → 22.24 | 23.57 → 28.60 | 2.71 → 2.46 | -25% |
| 平台目录，32 操作 | 100 | 9.06 → 9.19 | 11.18 → 12.00 | 0.99 → 0.92 | -25% |
| 平台目录，512 操作 | 20 | 18.68 → 20.81 | 20.94 → 26.64 | 3.41 → 2.19 | -84% |
| 平台目录，512 操作 | 100 | 9.67 → 9.39 | 10.62 → 11.39 | 1.36 → 0.85 | -84% |
| 租户目录，32 操作 | 20 | 21.05 → 24.17 | 24.89 → 27.84 | 3.60 → 3.68 | -17% |
| 租户目录，32 操作 | 100 | 8.78 → 10.45 | 11.40 → 13.36 | 1.34 → 1.33 | -17% |
| 租户目录，512 操作 | 20 | 31.45 → 23.76 | 41.14 → 26.81 | 5.47 → 3.85 | -43% |
| 租户目录，512 操作 | 100 | 13.80 → 60.18¹ | 16.12 → 174.75¹ | 2.53 → 2.29 | -43% |

¹ 租户大目录首轮 100 QPS Redis 组，压测客户端提交本身 P99 已迟到 88.9 ms（其余同 QPS 热读组约 2.5 ms），实发 98.3 QPS。保留原始结果，不将该组延迟归因于 Redis；对此组另做交叉复测。

平台 512 操作样本在两档负载下，数据库检查行数约 1,515 → 428、发送约 65.6 → 10.8 kB/请求。大菜单热读虽少约 33% 数据库发送字节，但实时准入仍要联表，检查与返回行数相同。版本切换窗口各请求 500 次，两个场景平均 9.004 条 SELECT（热读 9 条，首次缺失多两条读取）；未模拟持续目录写入。原始结果：[equal-qps-http.jsonl](./evidence/equal-qps-http.jsonl)。

租户 512 操作目录在新夹具进程按 SQL → Redis → Redis → SQL 交叉复测 100 QPS，各臂 600 次。复测实发 99.96–100.00 QPS，提交迟到 P99 约 2.5 ms，2,400 次请求无错误，Redis 1,200/1,200 命中。

| 轮次 | P95（ms） | P99（ms） | MySQL SELECT CPU（ms/请求） |
|---|---:|---:|---:|
| 1 | 14.37 → 12.76 | 24.11 → 15.19 | 2.52 → 2.00 |
| 2 | 12.04 → 12.89 | 13.49 → 14.77 | 2.38 → 1.96 |

首轮长尾未复现。两轮热读 P95 一好一坏，MySQL SELECT CPU 则稳定下降约 18%–21%，发送字节减少约 43%。原始结果：[tenant-large-100qps-repeat.jsonl](./evidence/tenant-large-100qps-repeat.jsonl)。

## 接入建议

当前保留三个入口的合并直查。小操作目录的 Redis 热读没有稳定的尾延迟收益；大菜单场景虽减少传输，准入联表与返回行数仍在，延迟也没有稳定改善。把 512 操作量级的热点目录保留为首选候选：平台与租户大目录都稳定减轻数据库负载，接口延迟收益受场景影响。是否上七天缓存以目标环境中大目录的持续读取频次、版本更新间隔及数据库资源瓶颈为准。应用开通、菜单准入与用户授权继续实时。

## 回归

- 目录、开通、菜单装配与隔离 MySQL 双节点共 40 项回归通过，另有同首期夹具复测 1 项通过；原 100 租户性能场景和浏览器场景未启用。
- 包边界、HTTP 契约和框架表归属检查共 24 项通过。
- 长缓存实现仅存在于隔离夹具。生产代码不引入缓存配置、额外数据库字段或迁移。当前处于 `validating`，待目标环境验收。
