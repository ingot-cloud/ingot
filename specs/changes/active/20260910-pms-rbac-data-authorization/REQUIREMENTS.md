# Requirements

## 用户场景

1. 平台发布应用，默认提供给全部租户；申请制应用默认关闭，按租户开通；全局停用对所有租户生效。
2. 子管理员共享平台预设的用户管理权限，租户 A 追加部门管理后仅 A 的子管理员获得追加能力。
3. 用户同时属于 A、B 部门，只在 A 担任主管；审核权限只作用于 A 的授权数据。
4. 管理员调整菜单路径和层级，不改变权限码、角色绑定或接口权限；菜单创建可选择已有权限或快捷新建独立权限。
5. 订单只读角色和公告全量角色同时授予用户，不会因为公告的 ALL 而扩大订单范围。
6. 已登录用户被撤权，所有资源节点最多 30 秒后停止使用旧授权，无需等待重新登录。

## 业务规则

### R1 租户和应用

- 有效租户成员身份是业务授权前提。租户上下文缺失、成员无效时拒绝租户业务访问，不解释成跨租户权限。
- 应用全局停用最高优先级；启用时，无租户覆盖遵循默认开放/默认关闭策略。
- 租户显式禁止始终禁止；显式允许只在 `[validFrom, validUntil)` 内可用。未生效或到期不得回退到默认开放。
- OPEN 菜单与通配授权均不绕过应用可用性。应用授权是功能上限，不自动赋予普通成员角色。

### R2 角色与委派

- 平台预设租户角色共享使用，权限为平台默认绑定与当前租户追加绑定的并集，再受租户应用范围限制。
- 租户只能撤销自己追加的授权。需要比预设角色更少的权限时创建自定义角色，不增加拒绝覆盖模型。
- 租户管理员可管理租户有效应用内权限；子管理员需具备相应管理能力，且拟授予的功能、数据范围不超出自身。
- 平台运营角色禁止通过租户入口授予。授权校验覆盖角色分配、批量设置、用户编辑、权限绑定及数据规则修改等全部写入口。
- 部门角色必须绑定当前租户有效部门且用户属于该部门；同一用户同角色可分别绑定多个部门。离开部门同步移除对应角色绑定。
- 非部门角色的空部门表示租户级任职，不表示 ALL；角色组不产生继承。

### R3 权限及菜单

- 权限编码与菜单 path、routeName、viewPath、pid 独立，建立后不能通过普通更新接口修改。
- 精确权限只授予该能力，`:**` 授予命名空间内当前及未来启用的具体权限；不存在或停用的具体权限不可用。
- 新增操作不会把旧精确授权自动变为通配；操作权限不隐含 read；通配功能不自动给新资源配置数据范围。
- 受保护页面关联一个或多个同应用具体权限，以 ANY/ALL 判断；未关联权限不能保存为受保护页面。纯目录和 OPEN 页面不需要权限关联。
- 菜单可见性条件不等于页面全部操作列表。按钮和对应 API 检查同一个操作权限；read 表示读取资源，菜单可引用 read。
- 默认选择已有权限；快捷创建先调用独立权限创建接口，成功后选中，再保存菜单。操作者必须有权限创建能力。权限不能从路径派生，也不随菜单删除。

### R4 数据范围

- 按角色授权、资源、操作计算；只合并拥有当前操作的有效角色绑定，合并采用并集，再与当前租户条件取交集。
- ALL 仅表示当前租户当前资源全部数据；CUSTOM 是当前租户指定部门；SELF 使用资源归属用户字段，不固定等同 created_by。
- 部门角色的 DEPT/DEPT_AND_CHILD 从角色绑定部门展开；非部门角色从用户当前部门展开。
- 缺少数据范围规则默认无数据授权，不从角色全局 ALL 兜底；平台默认规则不得写入某个租户的部门 ID。
- 查询、更新、删除应使用相同资源操作规则；新增或修改数据归属须显式校验，不能依赖读过滤实现写安全。

### R5 在线授权和失败处理

- 业务权限以服务端统一解析为准，不能从旧 Session 或 JWT 权限集合并回。
- 授权快照绝对新鲜度不超过 30 秒，且不能跨越应用授权时间边界。L1/L2 读取和回填不得重置起算时间。
- 事务提交后清本地并通知其他节点；丢消息仍有新鲜度保证。过期刷新失败拒绝访问，不以旧授权 LKG 放行。
- 认证失败、明确无权限、授权服务不可用必须可区分；故障不返回看似成功的空业务结果。

## 边界与兼容

- 一次性同步升级，无新旧业务授权双轨运行；旧会话和刷新令牌统一失效。
- 保留现有具体权限 ID、编码和角色绑定，迁移不根据菜单路径重新生成操作权限。
- 本次不自动给所有 PMS 业务表注册数据过滤，不修改无关业务模块的数据归属规则。
- 业务审批流程、字段级脱敏、显式拒绝规则、自动推导操作依赖不属于本次范围。

## 验收标准

| 编号 | 必须通过的场景 |
|---|---|
| A01 | 默认开放/关闭、租户允许/禁止、未生效/到期、全局停用组合及边界时间正确 |
| A02 | 两租户共享预设角色，追加权限和数据规则互不污染，不能撤销平台默认授权 |
| A03 | 租户入口、用户编辑及批量接口不能授予平台超管；子管理员不能扩大自身功能、未来通配或数据范围 |
| A04 | A 部门主管/B 部门普通员工、同角色多部门绑定、单部门解绑和退出部门均正确 |
| A05 | 修改菜单路径/层级不改权限，删除菜单不删除操作；ANY/ALL/OPEN/纯目录正确 |
| A06 | 权限快捷创建独立鉴权；受保护页面空权限拒绝；菜单保存失败不删除已创建权限 |
| A07 | read 与 approve 独立；通配覆盖未来具体操作但不能覆盖停用权限/不可用应用 |
| A08 | 本人 OR 部门正确；公告 ALL 不扩大订单范围；新资源无规则拒绝 |
| A09 | 列表、详情、更新、删除、创建及归属变更校验一致；别名、关联查询及分页总数无越权泄漏 |
| A10 | 嵌套调用恢复外层范围；缺少租户/映射/上下文默认拒绝；异步无显式上下文不得继承放行 |
| A11 | 多节点撤权在 30 秒内生效，丢失通知、过期 L2、缓存回填及远端故障不续期 |
| A12 | 新登录和已有会话采用相同有效权限；客户端 scope 不可伪装为业务授权；旧 AT/RT 不能绕过切换 |
| A13 | 迁移对照仅出现批准变化，无法确定的映射全部解决；备份恢复与整体回滚演练通过 |
| A14 | 平台默认角色规则、租户追加规则及部门上下文在示例中完成端到端验证 |

以上每项须在 TASKS 验收时附测试或联调证据，不以勾选任务代替结果。
