# Requirements

## 用户场景

租户管理员在成员页批量导入新成员，或导出通讯录后在本地改表再回写。任务异步登记，完成后下载工作簿、错误报告或一次性初始密码。组织拥有者不能通过表格改任职。已移出成员不出现在更新导出，回写也拒绝。

## 业务规则

1. 创建模板列：姓名、手机号、邮箱、部门。更新导出比空白模板多「成员 ID」。不可见字段列不出现。
2. 部门单元格从根部门名开始用 `/` 分层；多个部门用英文逗号分隔，第一项为主部门。不自动建部门。路径不存在或有歧义则该行失败。
3. 创建行复用入职：新账号、已有账号加入、已移出重新加入。不逐人返回密码；新账号初始密码写入该次任务的一次性下载。
4. 更新行按成员 ID 写姓名、手机号、邮箱和任职。姓名或手机号为空、成员不存在、已移出、单元格含脱敏星号则该行失败。邮箱为空表示清空；部门为空表示清空任职。不改账号状态，不重置密码。组织拥有者的任职变更该行失败。
5. 数据行上限为命名常量 `1000`。每一行独立成功或失败，不因一行错误回滚整份文件。
6. 创建导入要 `iam-tenant:member:create`。导出要 `iam-tenant:member:export`。更新回写要资料更新或任职权限，并继续校验版本、范围和字段策略。
7. 任务保留 24 小时。历史只返回当前操作者最近 10 条导入任务，只记条数不返回密码。
8. 现有 JSON 导出接口保持不动。

## 边界与非目标

- 已暂停成员可以出现在更新导出并允许回写资料与任职。
- 文件不是 xlsx、超过行上限、缺少表头时整份任务失败，不逐行提交。
- 密码文件首次下载后清除，再次请求视为对象不存在。
- 部门页导入导出不在本次范围。

## 验收标准

- [ ] 空白模板与更新导出列符合可见性规则，部门路径可解析且不自动建部门
- [ ] 创建行走入职，更新行走资料与任职，逐行独立成败
- [ ] 组织拥有者任职变更失败；已移出不导出、不回写
- [ ] 空邮箱/空部门按清空解释；空姓名或空手机号、脱敏星号失败
- [ ] 新账号密码仅一次性下载；历史只记条数
- [ ] JSON 导出三步接口行为不变
