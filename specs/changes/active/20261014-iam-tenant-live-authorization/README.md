## 目标

组织创建时指定的拥有者动态拥有本租户有效开通应用的全部权限，包括后续新增操作。共享角色由平台维护、租户只读；私有角色由租户直接创建并独立维护。租户分配引用角色身份，权限修改提交后自动生效；租户不再选择版本、发布或升级。委派使用角色白名单和资源范围上限。

## 确认记录与施工门禁

2026-10-14 用户确认了以上模型、只读改造方案，以及四项细化决定：

1. 委派按资源限制范围；同资源新增操作跟随角色，新资源补齐上限后生效。
2. 拥有者覆盖租户字段隐藏、脱敏、可编辑限制，保留平台强制约束和资源真实能力。
3. 保留已有 IAM 数据，必须提供迁移预检和回滚。
4. 历史分配统一采用角色最新已发布权限，存在参数或范围冲突时先处置再迁移。

工件已由用户评审批准，TASKS 决策完整，实施完成，进入验证。2026-10-19已授权本地提交，不提前修改 current；实际数据库切换另按运行手册执行，隔离测试不代表实库已切换。

## 范围

包含拥有者身份求值及生命周期、应用菜单与字段执行、共享及私有角色当前权限、租户分配/委派/候选/诊断、租户执行授权新鲜度、公共 DTO 和路由、已有数据迁移、正式目录同步、前端交付与联合验收。

平台自有角色的固定版本、字段权限和批量应用任务保持既有行为。本次不包含 Member 用户体系、认证协议改写、平台代入租户、从共享复制/继承角色入口、多层角色继承、SSE/WebSocket 推送、通用缓存重构或全仓库清理。
