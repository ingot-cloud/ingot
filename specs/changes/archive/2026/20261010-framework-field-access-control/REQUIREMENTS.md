# 需求

2026-10-10 用户明确批准并要求实施对话中最终公共字段访问控制计划。此前 Plan 已确认全部关键选择。

## 行为

1. 逻辑字段由资源目录集中定义，后端注解仅绑定实际属性和已实现的读、写、筛选能力。完整资源身份为 domain/applicationCode/resourceCode。允许保存未绑定字段，但未接入能力不可授权生效。
2. 按实际对象判断 FULL/MASKED/HIDDEN；隐藏不返回 JSON 属性，脱敏后端处理，完整保留原值。公共引擎不依赖 MemberFieldKey。
3. 编辑、筛选为独立操作定义；删除字段排序权限。MASKED 可编辑，编辑草稿为空，不补取原值。HIDDEN 不可编辑。
4. 操作能力按当前查看者、资源、精确操作统一求值；平台写字段仍保留授予来源的独立对象范围，不跨角色拼接。
5. 平台由固定角色版本授予字段权限；租户保留按查看者和目标范围的隐私规则，拆出无目标范围的查看者级编辑/筛选规则。通讯录不授予管理编辑。
6. 原值筛选需要已接入、获准筛选且本次有效查询范围内完整可见。不能按当前页样本放行，不静默丢弃未获准条件。
7. PATCH 区分缺键与显式 null；脱敏字段未触碰不提交，明确清空才提交 null；后端未知字段、只读字段、权限、业务校验及乐观版本双重保护。
8. 首轮迁移平台/租户成员、通讯录、成员关联返回、导出及 iam-ops。加入 joinedAt/lastLoginAt/updatedAt 可见性，仍只读并保持各场景原有返回范围。
9. 预设手机号、邮箱、全遮盖；自定义保留头尾或指定区间，不开放脚本或正则；仅文本支持 MASKED。
10. 共用分层缓存及版本化派生索引；读授权 TTL 不超过30秒，写 fresh，无 LKG/地板放行。启动预热本服务资源及公共默认策略，不预热所有用户、租户或对象。

## 边界

不生成业务 SQL，不增加未实现搜索能力，不改变固定业务排序、身份/对象门禁、角色升级、OSS 和时间契约。不执行真实库重建，不自动提交或部署。未投产，直接替换字段契约及正式初始化，不保留旧字段模型兼容开关。2026-10-10用户追加要求提供保留现有数据的离线迁移SQL；仅制作脚本并在隔离库验证，不执行目标库。

## 验收

隐藏属性实际缺失、脱敏无原值、别名/多个 DTO/同名资源隔离、脱敏编辑保留与清空、范围来源不拼接、字段新增安全关闭、筛选/count/导出同策略、缓存失效与到期/故障拒绝、逐行无授权 SQL/RPC，以及两端类型/构建/隔离数据库验证。自动化与真实用户/部署/性能验收分别记录。
