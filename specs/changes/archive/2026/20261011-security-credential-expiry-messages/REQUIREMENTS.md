# Requirements

## 用户场景

新建账号或管理员重置后，用户超过初始密码有效期未改密，登录失败应提示“初始密码或重置后的密码已过期，请联系管理员重置密码后再登录。”。管理员可在独立 Nacos 文件修改各场景文案，后续登录生效。

## 业务规则

1. 场景为初始／重置密码过期、普通密码硬过期、未知原因过期；同时命中时初始密码提示优先。
2. `credentialsNonExpired` 仍唯一决定凭证过期阻断，分类不能解除阻断；软过期宽限继续允许登录。
3. 配置键为 `ingot.security.login.messages.initial-password-expired`、`password-expired`、`credentials-expired`，统一归属各环境 `in-security-messages.yml`。
4. 缺文件、缺键、空白文案回退各场景内置默认；修改、删除配置后不残留启动快照。文案是纯文本，不执行模板。
5. 平台与租户共用 Auth 配置；外部响应结构、状态、错误码保持现状，BFF/前端透传消息。

## 边界与非目标

- 新建与重置不增加持久化来源字段；共享一个提示。
- 不改变策略来源、密码有效期、宽限次数、改密访问权限、认证检查顺序或异常放行策略。
- 不扩展其他登录失败提示、即将过期／宽限提醒、租户自定义、管理页面、数据库或前端代码。
- 缺失、未知、异常类型的内部原因用通用提示并保持阻断。

## 验收标准

- [x] 三场景及双过期优先级正确，原有准入规则保持（自动化验证）。
- [x] 原因经 RPC JSON 保留，锁定 meta 不丢失；异常原因可靠回退。
- [x] 三个独立配置、缺省／空白、修改／删除及文件缺失均符合规则。
  - 自动化验证配置修改／删除、空白及缺省；V3 由用户于 2026-10-12 确认测试成功。
- [x] 真实认证 Provider 使用默认 checker，自定义 checker 可覆盖；Auth/BFF 保留状态、码和文案（生产 configurer／Provider／HTTP handler 与 BFF 定向测试）。
- [x] 定向自动化与 IAM/Member/Auth/BFF 编译通过。
- [x] 实际 Nacos 发布及平台、租户登录人工验收完成并记录（2026-10-12 用户确认；未提供逐项环境日志）。
