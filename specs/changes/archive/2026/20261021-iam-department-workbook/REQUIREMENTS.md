# Requirements

## 用户场景

租户管理员在部门页批量导入新部门，或导出部门表后在本地改表再回写。导出任务进入「我的下载」。导入异步登记，完成后可下载错误报告。

## 业务规则

1. 创建模板列：部门名称、上级部门、排序。更新导出在最前增加「部门 ID」。不导出人数、负责人、导航骨架。
2. 上级部门写从根开始的名称路径，分隔符 `/`。不自动补中间部门。路径不存在、同级重名导致不唯一、或形成环，该行失败。
3. 同一上级下名称必须唯一，含本文件中已成功的前序行。名称不能含 `/`，最长 128。排序留空按 0。
4. 部门 ID 由系统生成。创建行填写了部门 ID 则该行失败。不能通过导入再造根部门。
5. 根部门可以改名称和排序。更新根部门的上级列若出现且非空，该行失败。
6. 更新按列是否出现在表头判断：列不在表头不改该字段；名称或上级在表头但为空则该行失败。
7. 导出按树前序，保证上级行在下级之前。请求体 `departmentIds` 空或省略表示当前可见全部部门；非空时服务端展开其下级并与可见范围求交。
8. 数据行上限 `1000`。每一行独立成功或失败。创建要 `iam-tenant:department:create`，导出要 `iam-tenant:department:export`，更新回写要 `iam-tenant:department:update`。
9. 导入任务保留 24 小时。历史只返回当前操作者最近 10 条导入。产物只对发起人可见。
10. 逐行调用现有部门创建与更新，复用权限、范围和版本。每行读取当前部门版本再更新。

## 边界与非目标

- 文件不是 xlsx、超过行上限、缺少表头时整份拒绝，不登记任务。
- 负责人仍在部门详情维护。
- 单条创建接口的同级重名规则本次不改。
- 已有自定义角色不自动获得导出权限；租户治理模板角色授予导出。

## 验收标准

- [ ] 空白模板与更新导出列符合规则，路径可解析且不自动建部门
- [ ] 创建行走 `create`，更新行走 `update`，逐行独立成败
- [ ] 本文件前序新建部门可被后续行引用为上级
- [ ] 同级重名、未知路径、环、根部门改上级、创建行带部门 ID 失败
- [ ] 导出接入下载中心，工作线程重验导出权限
- [ ] 他人任务 404；历史只记条数
