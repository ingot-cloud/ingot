# 需求与验收

## 场景与目标

平台自定义角色已支持固定版本批量应用和多节点异步执行。未来租户可能使用同样流程，需要隔离平台身份、权限及分配规则，避免复制整个 worker。本轮先建立代码边界，不提前实现尚未确定的租户或 App 业务规则。

## 必须保持的规则

1. 同一套流程管理集合快照、配置、预检编排、幂等、任务状态、租约、事务和明细进度；平台适配器管理业务域相关访问与校验。
2. 本轮仍仅接受平台自定义角色、同角色已发布版本和具备独立分配升级治理资格的有效平台身份。候选、明细及计数使用原有可见性边界。
3. 旧任务仍按保存的平台账号和成员恢复当前有效身份；不继承 HTTP 上下文，不保存登录令牌，不通过角色字段推断并启用租户执行。
4. 保留目标版本双向应用、逐条范围兼容复用、委派限制、fresh 写校验、冲突暂停和显式重新预检后继续。已提交批次不回滚，其他角色授权不受错误撤销。
5. 保留授权→角色→任务/分配的锁顺序、30 秒数据库租约、最多 100 条事务批次、分配/明细/审计同事务和提交后缓存失效。
6. 保留提交后唤醒、通知故障隔离、队列去重、60 秒正常补偿扫描及错峰、60/120/240/300 秒错误退避、250 毫秒续批、256 队列容量、已有指标和退出行为。
7. 适配器复用现有服务及查询，不增加逐条身份恢复、角色读取、周期监控 SQL、缓存或调用链中的重复授权。错误和不可用仍 fail-closed。

## 边界与非目标

- 不新增数据库列、表、迁移、授权域或主体类型；不更改 API、DTO、契约生成结果、前端和配置键。
- 不实现租户应用、跨租户共享版本推广、独立 App 用户模型或运行时业务域选择。
- 不新增适配器注册中心、插件发现、通用任务状态、任务控制台或通用重试平台。
- 不接入 TSS Cron 或 XXL-JOB 触发。只补充职责说明和共存验证；TSS 不承担角色明细、事务或审计。
- 沿用原“升级分配”接口最多 100 条且只支持更高版本的契约。

## 验收标准

- [x] A1：共用流程不直接使用平台身份恢复、平台权限/角色常量、平台分配查询或业务锁；只有一个平台适配实现，通过构造注入接线。
- [x] A2：准备、发布并准备、配置、确认、预检、候选与分布、历史任务读取的结果及错误契约保持一致，旧任务无需迁移。
- [x] A3：非平台身份、非平台自定义角色及不同角色目标被拒绝；工作线程撤权和依赖不可用仍回滚当前批次并暂停。
- [x] A4：超过 100 条、多节点竞争、过期租约接续、并发修改和重启恢复，无重复分配更新或漏审计。
- [x] A5：去重、执行中提示、队列溢出、扫描错峰/退避、通知故障和关闭等待保持原行为，没有新增查询。
- [x] A6：Spring TSS 与 worker 共存，无重复注册、Bean 冲突或共享执行线程；TSS 类型配置不控制角色 worker 开关。
- [x] A7：相关单元与隔离 MySQL/HTTP 回归、TSS Spring 测试、契约生成检查及静态依赖边界检查通过；明确记录人工验收状态。
