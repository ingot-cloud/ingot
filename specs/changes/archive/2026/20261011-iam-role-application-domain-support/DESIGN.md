# 设计

## 1. 收敛后的架构

保留现有类和运行机制，仅增加 IAM 内部 `RoleApplicationDomainSupport` 接口与 `PlatformRoleApplicationDomainSupport` 实现。接口不进入公共框架；本轮只有一个 Spring Bean，直接构造注入，不增加注册中心或路由配置。

`RoleApplicationScheduler → RoleApplicationWork → RoleApplicationService → RoleApplicationDomainSupport`。

- 调度器继续负责本地排队、时序和发现调用，不获取身份、角色类型或业务权限。
- `RoleApplicationService` 保留任务持久化、集合与明细管理、预检编排、事务、租约及提交后提示；仍实现 `RoleApplicationWork`，不另建重复的 facade/engine。
- 平台适配器封装角色发布/读取、身份恢复、准入和范围、授权及角色锁、分配访问、快照与预检写入，复用现有 IAM 服务和 Repository。

## 2. 内部接口边界

接口使用已有 `IamAdmission`、`ObjectScope`、角色/分配 DTO 和内部持久化类型，不新增泛型任务信封或任意 JSON 上下文。

| 操作组 | 适配器职责 |
|---|---|
| 准入与身份 | 当前请求治理准入；按任务保存的账号/成员恢复当前有效身份并重新检查治理资格 |
| 范围与角色 | 取得普通读或 fresh 执行范围；检查角色 READ、平台自定义种类和归属 |
| 业务锁 | 先授权锁、后角色锁；事务由共用流程管理，不在适配器开启新事务 |
| 版本 | 发布；读取固定版本；校验目标属于同一角色且支持应用；构造固定版本引用 |
| 分配访问 | 原查询的游标扫描、候选分页、分布及按 ID 读取；保留同一对象范围和 SQL 关系谓词 |
| 分配处理 | 原 `applicationSnapshot`、`previewApplication`、`applyApplication`；复用范围、委派、审计及缓存处理 |

共同的来源版本同角色检查、任务与角色关联检查、状态及乐观锁判断继续留在共用流程。现有 `IamAccess` 仅供共用流程发号；平台准入迁入适配器。保留 `TransactionTemplate` 初始化需要的显式构造器，其他新 Bean 使用 final 字段与构造注入。

worker 配置改为注入 `RoleApplicationWork`；生产仍由现有服务唯一实现。适配器不持有任务状态或节点 lease owner。身份和范围在原来的调用点获取，不能缓存准入或提前复用旧授权。

## 3. 事务、兼容与性能

保持当前 prepare/confirm/claim/execute/pause 的事务边界、顺序及失败语义。适配器是现有业务调用的封装，不再添加身份/角色解析查询。身份域不匹配在内存中拒绝，角色和版本使用现有查询判断，不依据通知恢复业务上下文。

既有任务结构缺少租户上下文，因此仍只解释为平台任务。平台适配器拒绝非平台身份及不支持的角色；不将本轮抽象描述成已经支持租户执行。将来租户接入必须另建 change，明确持久上下文、路由和门禁；App 客户端不自动构成新授权域。

公开接口、DTO、任务表、配置及事件保持不变；无需迁移或重新生成对外契约，不修改前端。原升级接口及批量应用共用的算法不移动或重写。

## 4. TSS 职责与扩展边界

当前 TSS 为 Cron 调度和管理抽象，角色 worker 还需要提交后立即唤醒、按 ID 续批、错峰与退避。本轮不修改 TSS 接口或运行实现，仅在 TSS 架构说明和 IAM 运行文档中写明边界。

未来若接入 TSS，入口只请求发现/唤醒，必须关闭重复的内部发现来源并保留现有时序语义；TSS 触发成功不能表示角色应用完成。Spring 或 XXL-JOB 的触发方式不替代数据库租约、事务及当前授权校验。其他业务出现明确共用需求后，再评估向 TSS 提取执行能力。

共存验证覆盖 Spring TSS 实际装配及 `ingot.tss.type=xxljob` 配置对 worker 的独立性；后者不等于真实 XXL-JOB Admin 集成测试，不新增 XXL-JOB 生产依赖。

## 5. 发布、回退与验证

仅后端滚动升级；旧新节点共用已有租约和任务结构。回退代码后仍能读取任务、进度和审计，无 DDL 回退。适配器不能改变处理集合、权限范围或覆盖既有分配。

复用既有 MySQL/HTTP 场景验证平台业务与真实多节点事务；增加适配器身份、角色/版本及锁边界测试，以及共用流程通过替代内部适配器执行的测试。虚拟时钟与通知测试继续验证调度语义；Spring 装配检查验证接口注入和 TSS 共存。

静态检查确认共用服务无平台常量和平台业务依赖，契约 `--check` 确认生成结果未变。查询次数/调用顺序由适配器针对性测试与现有轻量发现测试核对，不增加运行时监控查询或基准测试平台。全部结果记入本 change；人工验收后才更新 current 并归档。
