# 设计

两域组列表增加 view=SUMMARY，沿用默认完整信封、原分页、排序和筛选。默认页大小仍为 20。摘要分页最多执行两条列表查询，分别读取筛选后的总数与本页记录。摘要使用同一组对象范围，只返回元数据、版本和操作能力。显式只读列表接入请求内授权上下文。空页跳过组能力及关联装配。完整页按当前页组 ID 读关系，使用既有成员和部门范围投影，在 MySQL 按组聚合去重后的有效成员。写入沿用独立校验及乐观锁。

两端组工作区和选择器走摘要，独立成员分页。查看及编辑读取目标组详情，完整编辑按详情能力和版本提交，选择变化时丢弃旧结果。

场景错误限 IAM。应用域及部门查询用途缺失或无效、组 JSON 格式错误返回 400 InvalidArgument。空组名沿用原业务码。指定对象详情的默认 404 文案增加类型，包含账号、角色版本和租户委派。对象不存在与不可见返回同一文案。接口保留 `code=ObjectNotFound` 供程序判断，页面显示 `message` 中的中文业务文案。

数据库沿用现有结构及索引，缓存沿用现行策略。先发布兼容后端再发布前端，回退反向执行。

写入提示复核覆盖两端角色、应用目录、菜单和角色分配。已知业务分支返回具体的字段校验、引用、对象缺失或委派原因。通用失败按匹配的管理面路由补充操作对象。不存在与不可见使用同一文案，不回显受限记录名称。保持原校验顺序及事务，非法租户分配 ID 按既有参数契约返回 400。

2026-11-10 继续处理三项验收问题。字段权限上下文读取当前快照后，一次确认拥有者身份与任职并编译查看者规则，复用同一份结果计算列和各动作能力。普通字段投影的目录动作只解析一次。租户分配在已按权限分页的行内批量加载角色头、当前定义、开通动作及委派事实，统一计算操作能力与委派状态。所有批量数据限定可信租户和当前页。写入保留独立校验及原角色锁，不引入跨请求缓存。

无关键词时先从分配关系表计数和分页，再读取页内角色、成员和组名称。有关键词时保留原匹配范围。委派事实以递归查询覆盖组的部门继承，并与分页时读取的分配版本核对。版本变化时按无有效委派处理。

框架 HTTP 边界对未预期异常与参数解析失败返回固定中文提示，原始异常留在服务端日志。明确的业务、认证和加密协议错误保留原有错误码和契约。网关未预期错误返回 500。异常响应不返回鉴权实现细节。

## 10 万条分配分页

同批基线的首页取数约 0.24 ms，精确计数约 280 ms。第 4,000 页取数约 377 ms，原计划扫描 10 万条租户分配、回表并排序。原型使用以租户、管理域和分配 ID 起始的覆盖索引，计数约 22 ms、深页取数约 18 ms。保留精确总数和页码跳转。索引覆盖角色、主体类型、委派来源和主体 ID，分页先筛出分配 ID，再用主键及原有连接读取页内投影。条件同时用于分页和计数。仍按分配 ID 升序，不改变空范围拒绝规则。精确计数和深页保留线性索引扫描。

名称搜索继续使用转义后的包含匹配，查询当前租户成员和组、当前租户私有及共享角色的匹配 ID，按关系内的主体或角色 ID 判断是否命中。保持 OR 语义，命中多个名称时每条分配只算一次。当前角色引用由复合外键保护，只有旧的无角色撤销历史继续排除。权限及租户条件仍在 ID 取页和计数前应用。

首次使用完整夹具时 MySQL 为 `role_id IS NOT NULL` 选了覆盖索引跳跃扫描，计数约 168 ms，深页取数约 129 ms。单独禁用跳跃扫描又让计划退回成员索引。计数和内层 ID 取页仅在没有对象或委派来源限制时提示使用覆盖索引并禁用跳跃扫描。受限查询仍由优化器按对象 ID 或委派来源选择索引。

深页内层取到 20 个 ID 后，优化器曾选择从角色表向分配表连接，再与 ID 页过滤。外层查询用 `JOIN_PREFIX(page_ids, ra)` 从页内 ID 查分配主键，之后才读取角色和主体名称，避免物化 ID 页后重新扫描大量分配。

已有库先运行 037 在线加索引，再发布后端。旧后端兼容新增索引，新查询无索引仍可执行。回滚应用后可以单独删索引，保留分配数据。新建库直接带索引。验收用同一夹具要求各场景 P95 下降，确认精确结果和范围，验证 Druid Wall 及迁移执行和回滚。
