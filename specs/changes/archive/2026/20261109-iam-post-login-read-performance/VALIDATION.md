# 验收记录

## 环境与口径

- 隔离 MySQL 8.4 与两个真实 IAM HTTP 控制器节点。测试过滤器恢复合成身份。连接池上限 64，新旧版测试 JVM 堆上限均为 2 GiB。
- 基线使用 `f7feb1fb` 的业务代码。候选版使用本变更。单租户新增 10 万成员和 100 万条关联，其中 90 万条任职、10 万条直接组关联。平台新增 1 万平台成员和 10 万条直接组关联，账号表与租户共用。
- 常规首屏使用 20 个各含 100 个直接成员的组。另测万级直接绑定组和部门继承产生的 10 万有效成员。前一版让首屏直接返回约 1.1 MB 的旧完整列表，压测触及默认堆上限，保留为额外压力证据。
- 每轮先暖读，再按固定速率发出 80 次 20 QPS 请求。新版额外发出 400 次 100 QPS 请求。配对结果使用各轮分位数的中位数。API 链路包含列表和首个组的成员分页，浏览器渲染单独验收。

## 数据库与容量

- 平台 100 QPS 发起速率 99.96 QPS，P95 9.3 ms，P99 10.5 ms，错误 0，最多 0 个连接等待者。
- 租户 100 QPS 发起速率 99.98 QPS，P95 14,504.8 ms，P99 14,811.0 ms，错误 0，最多 136 个连接等待者。
- 租户 capabilities 从小样本扩到 10 万成员后，查询次数仍是 6 条，检查行数从 181 增至 100,218。版本聚合对同一租户的成员行执行 COUNT、SUM 和 MAX，执行计划检查 100,004 行。它是高并发下独立于用户组分页的成本，需另行评审版本计算设计。
- 租户成员深页偏移 80,000 使用成员状态覆盖索引，扫描 80,020 个索引条目。大组直接关系偏移 8,000 使用关联主键，扫描 8,020 条。后续索引或游标方案应以对应调用量和计划为依据。
- 租户角色关联 10 万有效成员后，第 4,000 页仍返回 20 人、总数 10 万。此请求执行 11 条 SELECT，检查约 10 万行，实测约 758 ms。另一租户读取同一角色返回 404。
- 平台首批组成员查询的展示能力仍有逐成员重复读取。后续可复核平台人员页现有的批量能力装配能否覆盖该入口。

- IAM 全量测试执行 1,494 项，通过 1,494 项，另有 5 项可选用例跳过。单独重跑隔离 MySQL 写入场景，确认应用及菜单新增、更新、删除、重复编码、菜单层级、角色被分配时拒绝删除、接收对象不可见、无效分配标识和撤销。前端验证保留草稿及单次提示。
- BFF 28 项、网关 41 项、Auth 16 项通过。Auth 中 Redis 与 MySQL 两项时间契约用例使用独立实例补跑。两端 Chromium 同源登录夹具通过，验证会话回读、退出、租户选择、隔离和拒绝路径。实际账号通过 Auth 登录后读取 IAM，真实浏览器 BFF 验收仍单列。
- 权限回归覆盖跨租户、来源撤销、有效期、停用、会话重放、CSRF 和入口绑定。本轮测试范围内未发现越权通过。修复租户分配写入直接解析非数字编号导致的 HTTP 500，改按参数错误返回。框架通用异常处理仍可能将内部异常文本写入响应，该行为属于共享框架的错误响应契约。
- 租户成员字段权限上下文四次均执行 75 条 SELECT，实测约 478–663 ms。当前实现为读、创建、更新分别构造字段判定，再单独计算列可见性，需进一步拆解重复 SQL。租户分配列表在本机小样本每次 10 条 SELECT，隔离样本平均 148 条，需按关系量复核每行成本。已移除委派给用户组时未使用的一次成员关联读取，保留原授权判断。
- 涉及加密写入、跨租户切换、异步任务产物或缺少现有对象的分支，按可复现的隔离用例或待验项记录。80 个读取场景与 246 条 IAM 路由契约采用不同覆盖口径。

## 2026-11-10 租户分配列表 10 万条分页

使用上一轮 10 万条分配的 MySQL 8.4 隔离夹具、租户拥有者和 HTTP 入口。每组请求每页 20 条，预热后测 20 次。计数和取页耗时读取实际 Mapper SQL 各自的 `EXPLAIN ANALYZE` 根节点，包含搜索判断、页内投影等 SQL 执行开销。HTTP P95 包含权限求值及响应装配。两组独立运行避免相互争抢资源。[完整执行计划及接口数据](ASSIGNMENT-VOLUME-PERFORMANCE.json)

| 场景 | 计数 SQL（ms） | 取页 SQL（ms） | HTTP P95（ms） |
|---|---:|---:|---:|
| 首页 | 280.00 → 17.20 | 0.24 → 0.23 | 420.55 → 29.92 |
| 第 4,000 页 | 285.00 → 16.60 | 377.00 → 14.60 | 684.77 → 40.79 |
| 名称包含搜索，命中 | 323.00 → 23.60 | 492.00 → 0.23 | 835.37 → 32.17 |
| 名称包含搜索，未命中 | 337.00 → 19.40 | 337.00 → 20.90 | 701.86 → 51.15 |

- 首页旧取页沿主键很快找到 20 条数据，精确计数是主要耗时。旧深页计划按成员索引找到租户的 10 万条分配，回表并为偏移排序。新计划沿 `idx_iam_assignment_tenant_list` 按 ID 顺序筛选，第 4,000 页读取 8 万条索引记录，仅物化最后 20 个 ID。外层从这 20 个 ID 出发连接详情，避免优化器改从角色表重新关联全部分配。计数仍扫描 10 万条索引记录。计数和偏移的成本依然随扫描量增长。
- 搜索把成员、用户组和角色名称转换为匹配 ID，避免对全部候选分配逐条关联名称。继续按原有字符排序规则和转义语义进行包含匹配。包含鉴权的 SQL 次数在有结果时仍是 16 条，未命中时仍是 8 条。三种页大小和次页的 120 条夹具响应与修改前一致。
- 同夹具的初次复测里，MySQL 选择了覆盖索引跳跃扫描，导致首页计数约 168 ms、深页取数约 129 ms。单独禁用跳跃扫描会退回成员索引。最终仅在全租户可见的计数与内层 ID 取页提示使用覆盖索引并禁用跳跃扫描，受限列表继续由优化器按对象或来源选择索引。
- 已在隔离 MySQL 8.4 对旧库执行 037 升级与回滚各两次，确认索引列顺序、分配数据及缺少索引时的计数可用性。初始化包、数据字典、结构快照及数据库审查报告通过生成一致性检查。
- IAM Provider 全量回归通过 1,498 项，另有 6 项可选用例跳过，10 万分配基准已单独执行。787 项 Druid Wall 用例全部通过。权限验证覆盖受限管理员委派来源、撤销、到期、组继承、空可见范围和跨租户隔离。搜索验证成员、组及角色名称、多个条件同时命中去重、特殊字符及主体类型筛选。037 尚未应用到运行环境。
