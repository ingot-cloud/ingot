# 需求与验收标准

- [x] A1 `bootstrap` 按当前可访问应用，一条 SQL 读取启用菜单与操作绑定；无可访问应用时跳过。保留菜单层级、排序、隐藏路由、路由参数、`OPEN`、`ANY/ALL` 和停用操作绑定的语义。租户开通与用户授权保持实时。
- [x] A2 平台与租户 `action-catalog` 在鉴权与租户开通检查后，一条 SQL 读取应用是否存在及目录内容。保留现行排序、空目录、停用过滤、名称回退及错误码。目录修改提交后下一请求看到新值。
- [x] A3 用首期夹具对比完整请求的 SELECT 数，并分别验证菜单有绑定、无绑定和目录为空。无表结构迁移、公共接口变化或新增缓存配置。
- [x] A4 采集可获得的目标环境平时与高峰 QPS，按路由及应用观察复用。无目标环境记录时说明缺口，并用可复现的合成负载验证。
- [x] A5 同 QPS 对比 SQL 与版本化 Redis 的延迟、数据库工作量和命中率，覆盖冷读或回源与热读。缓存候选只复用共享目录，实时菜单准入与授权相同。记录数据边界和是否有上线依据。

- [x] A6 本机 IAM 的直查制品通过平台和租户真实会话验收。目录分支每次各执行一条 SELECT，租户目录在开通检查通过后才读取。隔离双节点使用可控样本验证空目录、停用过滤、无权访问，以及目录、菜单、应用开通和授权变更提交后的下一次请求。
