## 流量与目录规模

在 IAM 侧按 `GET /v1/me/bootstrap`、`GET /v1/platform/applications/{id}/action-catalog`、`GET /v1/tenant/applications/{id}/action-catalog` 归并。每个请求只计一次，避免把网关转发和 IAM 日志累加。以实际请求计 QPS，含拒绝和失败；同版本复用只计成功返回目录的请求。平时使用每分钟平均 QPS 的 P50/P95（覆盖确认完整的区间，零流量分钟计零）；峰值同时记单秒和峰值自然分钟平均 QPS。只有 Sentinel 路由计数时，明确写出计数语义与覆盖范围，不据此分摊到应用。

以只读连接查询各应用的目录规模和采样时间。平台视图统计所有操作，租户视图统计启用资源下的启用操作。无操作应用保留零值。应用状态随快照保存，租户是否实际可见仍以当次开通和授权为准。[inventory.sql](../../../../../tools/iam/catalog_perf/inventory.sql)

## 同版本重复读取

按「平台/租户视图、应用 ID、该请求实际读到的目录版本」分组。每组成功读取 N 次，重复读取为 max(N−1, 0)；这个数表示观测窗口内的复用，和实际 Redis 命中率不同。目标当前的 `iam_application.version` 是应用自身的乐观锁，资源或操作变更不保证推进它。不能拿这个字段、路由总数、响应大小或相同内容指纹代替目录版本。相同内容指纹只能报告为相同内容重复，不能区分中间变更后恢复相同内容的情形。

只有从读取快照取得可信版本，或有完整的已提交目录变更时间线且能把读取一致地归到版本时，才记为版本已知。现有审计可辅助调查变更，但单凭审计目标 ID 或有限记录无法证明每次读取看到哪个版本。分别报告带版本的成功数、无版本的成功数和可确认的重复数。无版本数据填「未知」，不能记为零命中。目录版本只用于验收证据，不在本阶段给生产引入版本字段。

## 本地汇总方法

将确认完整的 IAM 访问窗口导出为 CSV，每条请求一行，仅需 `timestamp,method,path,status` 四列；有可信版本证据时增加 `catalog_revision`。时间戳带时区，目录路径含应用 ID；仅有路由模板时可以统计 QPS，但按应用归为未知。状态码以 IAM 实际结果为准，目录入口只将 HTTP 200 计为成功读取，只有成功返回目录的请求才能带版本。不要合并同一个请求的多份日志。指标源已聚合成每秒计数时，直接使用指标源计算路由 QPS，不展开成伪造的访问行。

已有只读 MySQL 登录路径的操作方可导出快照并在本地汇总（替换环境名、登录路径、数据库名及完整窗口）：

```sh
mysql --login-path=iam-readonly --database=ingot_iam --batch \
  < tools/iam/catalog_perf/inventory.sql > /tmp/iam-catalog-inventory.tsv
python3 tools/iam/catalog_perf/summarize.py \
  --environment iam-test --start 2026-11-02T00:00:00+08:00 --end 2026-11-09T00:00:00+08:00 \
  --access /tmp/iam-access.csv --inventory /tmp/iam-catalog-inventory.tsv
```

汇总器输出三条路由的状态码计数和 QPS、各应用平台/租户视图复用及覆盖数、以及可选的目录规模快照。原始访问日志和版本值不写入 SDD；使用汇总产物登记验收证据。

采集工具已在隔离 MySQL 中验证全部操作、租户可见操作和空目录计数。本地汇总已验证 QPS、视图分组和部分版本覆盖。
