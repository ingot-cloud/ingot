# 需求：同源登录与双入口部署

> 状态：completed；需求已获用户确认，代码已实施；真实环境验收见 VALIDATION.md。

## 1. 目标场景

R01：租户用户收藏本应用 /login/，打开即显示可操作表单；无 tx、旧 tx 或旧 ticket 不阻止进入表单。
R02：平台用户/租户用户在登录页停留一小时、隔天或设备休眠后提交，后台按需准备，不经过管理页再返回登录页。
R03：平台、租户分别认证、可同时在线；普通退出仅作用当前应用。只有平台资格的账号不被迫选择组织。
R04：纯 IP 无 DNS 场景使用 HTTPS 双端口；每个端口包含该应用登录和管理页面。有域名场景使用两个 origin，同样路径布局。
R05：网络丢响应、重复点击、多标签页、组织资格变化时，认证结果不串号、不重复签发、不误判旧会话。

## 2. 业务规则

- BR01：登录与管理必须同源，定义为 scheme/host/port 完全一致；只保留 platform-admin、tenant-admin 两个服务端应用注册。入口不是第三方 OAuth 客户端任意指定的 origin。
- BR02：/login/ 是稳定页面，不是短期凭证。打开页面不创建事务、不预弹滑块；用户明确提交时才获取 CSRF、创建新 LOGIN 事务并提交凭证。
- BR03：事务默认 600 秒，从创建计时；服务端 UTC 决定时限，GET、焦点与挑战重试不续期。选择阶段不能超过 Auth 预授权/state 的实际期限。
- BR04：匿名浏览器绑定和事务分开。一个有效绑定可承载多个独立事务；创建新事务不无条件作废旧绑定。每绑定默认最多 5 个未终结事务。
- BR05：平台无租户候选；租户零候选失败、单候选自动执行完整认证、多候选本页选择；每次均重验实时成员资格。切账号/组织重新认证。
- BR06：login/select 成功直接提交本域正式会话并设置 Cookie，响应 COMPLETED。浏览器 READY/ticket/complete 退出新协议；BFF→Auth 授权码及 PKCE 继续保留。
- BR07：正式会话使用全新随机 ID；匿名绑定不升级为正式会话 ID。Token、PKCE verifier、Auth Cookie、正式会话 ID 只在服务端。
- BR08：平台/租户正式及绑定 Cookie 名称分别独立；不设置父域 Domain。纯 IP 下不把端口误当 Cookie 隔离，按可信 appId 选择 Cookie、Redis 与身份。
- BR09：预备、取消、失败、网络错误不撤销原正式会话；最终成功替换同应用身份并撤销被替换 sid。另一应用不受影响；账号全局安全撤销仍按原规则。
- BR10：同事务认证/选择/提交只能执行一次；并发、丢响应通过事务结果和有界 resume 恢复，不能仅凭 me 存在某个会话当成成功。
- BR11：未认证准备问题可原地重建一次；已验证身份不得迁移到新绑定，超时或被撤销需重新认证。密码仅当前提交内存使用，认证阶段切换/取消/成功后清理。
- BR12：HYBRID、防重放、412、账号失败计数、锁定、禁用、初始改密与 sid 撤销语义保持；重建流程不能绕过安全策略。
- BR13：依赖故障与过期严格区分；不以服务故障清旧会话，不把 Auth 所有异常映射为事务过期。
- BR14：事务、会话提交与撤销采用条件推进/代次隔离；不能因迟到响应或旧完成结果恢复覆盖较新身份。

## 3. 范围与兼容

- 影响 BFF 浏览器契约、Gateway 入口及 Cookie 中继、注册表、Nacos 样例、部署文档、前端宿主与认证共享包。
- 同应用注册改为一个 origin；不保留四域名配置、跨域准备接口或 credentialed CORS。
- 旧页面地址只在当前 origin 规范化到 /login/；停用独立登录域由部署方显式引导，不自动接受 query 指定的目标。
- 保留既有 OAuth 内部客户端及 Auth 执行面，必要接入改动限定本登录链路；不在本次建设公开 OAuth2/OIDC/SSO。
- Cookie/Redis schema 和接口有破坏性变化，统一发布、一次重新登录；不声明新旧前端可混跑。
- 不改变业务数据模型，无业务 DDL 迁移。current 只在实现与用户验收后更新。
