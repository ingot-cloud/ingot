# Requirements

## 用户场景

| 场景 | 使用者与触发 | 期望 |
|---|---|---|
| S01 | 平台创建组织并指定 ownerAccountId | 指定账号成为本组织拥有者；无需额外分配角色即可管理和使用有效开通应用 |
| S02 | 给组织开通应用、给应用新增操作 | 拥有者自动获得权限；普通成员仍取决于当前角色及有效分配 |
| S03 | 平台修改共享角色 | 所有租户关联成员自动使用新权限，租户无需升级 |
| S04 | 租户直接创建或修改私有角色 | 仅本租户成员跟随，角色没有共享基础或继承关系 |
| S05 | 拥有者委派研发部授权管理员 | 管理员只向限定人群分配允许角色和范围，角色同资源新增操作自动跟随 |
| S06 | 转交拥有者或撤销角色/委派 | 后续授权请求按新事实执行，不依赖重新登录或失效消息送达 |
| S07 | 运维保留现有 IAM 数据切换模型 | 输出影响及冲突，未解决则阻断；可验证迁移及回滚 |

## 业务规则

### R01 拥有者身份与权限边界

拥有者资格由服务器核对当前 TENANT 身份的 memberId 与组织 ownerMemberId，且账号、成员、组织均有效。角色名称、角色码、JWT 中旧角色、客户端标志和同账号的平台身份不能授予该资格。拥有者动态获得有效开通且启用的租户应用全部启用操作，本租户全部数据范围。无权限目录注册或未实现资源执行器不能因拥有者资格开放。

应用未生效、到期、停用、操作停用仍约束拥有者。租户自己的普通应用人群/通讯录禁止范围/字段隐藏脱敏限制不反向限制拥有者。平台强制字段上限、真实只读字段、字段写/筛选注册能力、凭证安全及必须改密限制仍生效。全部数据范围始终包含可信租户边界。

创建组织不创建管理员、主管等默认私有角色，不复制共享角色，也不以固定 SYSTEM 分配维持拥有者资格。必要组织、成员、部门、开通及默认策略引用照常初始化。基础治理应用仍为必开，普通配置不能关闭最后治理入口。

只有当前拥有者可以转交组织所有权；目标为同组织有效成员。转交原子更新身份与审计，后续请求新旧拥有者权限切换，旧拥有者其他明确角色分配保留。不能以普通角色分配取得拥有者身份；不可通过普通成员操作停用或移出当前拥有者。

### R02 两类角色与当前权限

SHARED 归属租户域、无 tenantId，由平台维护；TENANT_CUSTOM 归属一个租户，保存完整权限。私有角色不接受 baseRevisionId、差异、版本名称或历史来源选择。共享角色只能由平台修改元数据、权限和启停，租户不可修改、停用或删除共享定义。

租户分配绑定角色 ID，直接成员与用户组使用相同当前定义。角色权限新增/删除/范围变化自动影响已有分配；多角色按各完整来源允许范围求并集，不能跨来源拼接功能和范围。移除一个角色的操作不构成全局拒绝。空权限角色可保存，表示不授予操作。共享角色可跨应用，但执行时仍逐应用核对租户开通。

内部不可变快照、并发修订和审计历史保留，不作为租户业务版本。角色停用关闭其全部贡献；被分配或委派引用的角色拒绝物理删除，撤销历史仍保留。

### R03 范围兼容与部分待配置

同资源同绑定类型使用稳定参数键。新操作可复用现有资源绑定；新增资源可引入新键。已有键不得在一次保存中改成另一资源或绑定类型，需使用新键并在预览提示。参数删除后旧绑定保留审计但不参与求值，不能影响其他有效操作。

角色保存后新参数缺失、不兼容、对象失效或缺少资源委派上限时，受影响操作不产生可执行范围，不能默认 ALL，不能从其他角色/委派补齐。旧有效操作继续执行；分配响应列出待补范围，不伪造整个分配已失效。后续通过普通分配/委派编辑补齐，不增加升级流程。新增分配提交必须补齐其当前定义所需参数，并校验归属。

### R04 委派授权

委派授予限定角色的分配资格，保存 allowedRoleIds、接收人员/部门、资源范围上限、有效期和最长分配期限。每次写入及执行均持续检查一条完整委派，不拼接多条来源。管理员不能通过扩大用户组、部门调整或角色参数间接越权。

经委派派生的角色权限随当前定义变化。同资源新增操作在角色、分配范围与该资源上限交集内生效；新资源没有上限时不生效。撤销/到期、白名单移除、接收者脱离人群等持续约束。租户保持现有限定单次期限，不在本次开放 UNLIMITED。

委派本身不授予角色编辑、继续委派、拥有者转交或业务操作权；独立直接授权仍按其真实资格求值。只凭委派的管理员可以进入受限分配流程，候选、回显、计数、列表与写入范围一致，只管理本人该委派产生的记录。禁止自授权及借用他人委派。

### R05 字段与资源执行

拥有者的字段结果来自同次可信授权与服务器资源能力，不使用浏览器“管理员”标志，不借用 platformAdministrator。成员管理、通讯录、导出、搜索、选择器、计数及已注册其他租户资源一致处理。普通成员继续遵守既有租户字段和通讯录策略，不新增普通角色字段权限模型。

### R06 实时性与失败语义

“即生效”指授权修改事务成功提交后，新发起的授权请求使用当前事实；不追溯中断已完成准入的在途只读请求。新增/移除权限、范围调整、拥有者转交及开通变更不要求重新登录。租户执行路径不接受跨请求的旧允许结论；消息总线丢失和缓存中残留允许结果不能维持撤销权限。

同请求内允许批量读取和复用一致快照。不可变角色内容可缓存，所有者、角色当前引用、委派、成员、开通等可变事实实时读取。基础设施不可用返回 503，不将旧允许结果/LKG 用作放行。

前端保存成功立即刷新当前会话与相关列表；其他可见租户页面按 expiresAt 刷新，正常网络下展示最多落后 30 秒。后台标签不轮询，恢复可见立即核对；失败退避、不以 UI 旧按钮授权、不自动重放写请求。快照标识仍为内部同步依据，不展示为角色版本。

### R07 存量与部署

统一最新权限可能改变历史分配，必须预检记录变化与冲突。私有差异角色物化其最新已发布版本实际合成权限，不把共享最新权限重新套进去。旧 SYSTEM 分配不能直接成为拥有者资格。不同操作的资源范围上限不一致时不得自动取并集。迁移详情见 MIGRATION。

公共接口为破坏性租户契约变化，采用维护窗口联动切换；禁止旧新租户契约混合放行。平台自有固定版本内容、批量任务与身份权限不随此次改造转换。

## 验收标准

- [ ] [ACCEPTANCE](./ACCEPTANCE.md) 中 B01–B24 均有明确证据；不能用 Mock 替代真实 HTTP/数据库/浏览器。
- [ ] 新建库和已有库得到同一目标模型；既有数据、审计、对象 ID 和必要引用可追踪。
- [ ] 保存角色不更新全部成员分配，跨租户共享更新及无消息失效场景正确。
- [ ] 迁移预检阻断、重复执行、故障恢复及两类回滚演练通过。
- [ ] 两端接口一致、平台既有行为回归通过、性能报告满足 DESIGN 的预算。

## 非目标

不新增其他默认角色、共享继承或复制入口、租户业务版本、多层委派、平台代入租户、新业务应用、SSE 推送、Member 改造。数据保留仅针对现有 IAM 目标表，不恢复旧 PMS 表的运行依赖。
