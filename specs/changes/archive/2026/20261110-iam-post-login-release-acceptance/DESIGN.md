# 验收与回退设计

确认目标环境、账号、版本、数据库和操作窗口后采集。会话通过实际登录链路建立，按入口现行规则完成验证码。性能对照沿用已归档方案的测量口径，记录采样时间、次数、数据规模、连接池和冷热状态。缓存指标按实际接入情况记录。

已有库使用 [037 在线索引迁移](../../../../../databases/iam/migrations/037_tenant_assignment_list_index.sql)。在经批准的发布窗口先加索引，再切换兼容后端，最后切换管理端摘要视图。回退按管理端、后端、索引的顺序执行，保留分配数据。新建库使用当前初始化包。

记录实际生效版本后，在 IAM 用户组、读取性能、租户即时授权、数据库持久化及管理端用户组和错误处理能力中同步运行基线。保留已归档的本地验收原始结果。

## 现场操作

- 页面前后对照使用旧版后端 `f7feb1fb`、前端 `dd3ec45`，以及新版后端 `d40d3dff`、前端 `9682655`。切换窗口确认后，两版在同一入口、同一浏览器会话、同一测试库及造数上顺序运行，两端均使用相同的前端构建或开发模式。记录服务版本、JVM 与 Redis 冷热状态，沿用点击到可见成员首行后两帧的计时起止点，舍弃 3 个预热样本后各采集 20 次，并核对两端 P95 降幅。对照后恢复当前运行版本并清理临时数据。
- 本机平台授权读请求实际访问 `iam-authorization` 分层缓存。租户授权每请求实时求值，单独验证权限与延迟。本轮由本机临时探针记录 L1、L2 命中和向下一层读取的次数，以及加载器调用次数。先等测试会话的缓存自然过期，连续读建立热缓存，再在 Redis 值仍有效时单次使采样请求对应的 L1 条目失效，验证 L2 命中和 L1 回填。每层以命中数除以该层命中与未命中之和，零次访问记为无样本。采样不记录身份、缓存键或内容；结束后恢复原始字节码，不新增管理端接口或指标。受控流量比例用于验证缓存行为，长期命中率需要自然流量和持续观测。
- 现场受限成员验证需要一个非拥有者的有效租户会话。用临时身份验证同租户允许读取和超范围拒绝，再确认外租户数据不可见。现场临时身份只关联验收数据，登录若出现验证码由用户处理。
