# Requirements

## 用户场景

1. 管理员在成员导入导出页发起导出，接口立即返回，页面提示「已提交，可在我的下载查看」，不再等待生成。
2. 管理员随时打开「我的下载」，看到自己发起的导出：名称、来源、状态、创建时间、过期时间、失败原因。
3. 任务成功且未过期时，点击下载获得文件；过期或失败时不可下载。
4. 后续其他模块的导出接入后，同样出现在该列表中。

## 业务规则

1. **按人隔离**：只返回当前身份（认证域 + 租户 + 成员）发起的任务。他人任务按不存在处理（404），不暴露存在性。
2. **权限复核**：下载时按来源重新校验原导出权限。例如成员导出需仍具备 `member:export`，否则拒绝。列表本身只要求已登录租户身份。
3. **不重新生成**：下载返回的是生成时的文件快照，字段可见性与脱敏以生成时为准；不提供按新权限重新生成。
4. **保留期 7 天**：从创建起算。到期后删除 OSS 对象，任务标记 `EXPIRED`，列表仍显示但不可下载。任务记录 30 天后清除。
5. **文件存储**：只存 OSS，库内保存 `bucket/objectName`。下载时签发短时效链接（5 分钟）；签名失败返回错误，不回退原始路径。
6. **状态**：`PENDING → RUNNING → SUCCEEDED | FAILED`，过期后 `EXPIRED`。失败只返回可展示的原因，不返回异常堆栈。
7. **异步执行携带认证**：任务在异步线程执行时沿用发起时的认证上下文，生成逻辑可复用现有权限与字段投影。
8. **成员表格导出**：`POST /v1/tenant/members/workbook/export` 登记下载任务并返回任务 ID，导出内容与现有设计一致（全部或指定成员、隐藏列省略、脱敏带星号、排除已移出）。

## 边界与非目标

- 节点重启时正在执行的任务：启动后无法续跑，清理任务把超过执行超时（30 分钟）仍为 `PENDING/RUNNING` 的记录标为 `FAILED`。
- OSS 不可用：生成阶段上传失败则任务 `FAILED`；下载阶段签名失败返回服务不可用，任务状态不变。
- 不迁移成员 JSON 导出，不迁移导入相关文件。
- 不做平台域入口、跨服务登记、删除与重新生成。

## 验收标准

- [ ] 发起成员表格导出后接口立即返回任务 ID，任务最终 `SUCCEEDED`，文件位于配置的 bucket 中
- [ ] 「我的下载」列表只包含当前成员在当前租户发起的任务，按创建时间倒序分页
- [ ] 他人任务的详情与下载链接返回 404
- [ ] 失去 `member:export` 后，已有成员导出任务下载被拒绝
- [ ] 签名失败时下载接口报错，不返回原始对象路径
- [ ] 过期任务删除对象并显示 `EXPIRED`，不可下载
- [ ] 超时未完成的任务被标记 `FAILED`
- [ ] 时间字段按 ISO-8601 UTC `Z` 返回
- [ ] 现有导入、导入历史、错误报告与一次性密码行为不变
