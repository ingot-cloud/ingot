# 设计

确认RUNNING的数据库事务登记afterCommit事件，仅提交成功发布本地提示。监听器本地立即入队，同时通过独立有界发送线程异步调用现有InvalidationBus；总线自消息过滤由独立本地唤醒补齐。远端仅按任务ID入队，随机延迟200～1000毫秒；重新查询任务确定角色、租约及当前身份，不信任通知内容。总线缺省时本地和扫描仍可工作；worker关闭的HTTP节点仍可广播。

调度器、扫描线程、单执行线程、通知发送线程相互分离，生命周期由Spring管理。队列按任务ID去重并保留执行中标识；批次结束仍有工作时250毫秒后排队，执行中到达的新提示在结束后合并处理。默认容量256，溢出提示留待兜底。定时器只安排回调，不查询数据库。

首次扫描在0～配置扫描间隔内随机分散；正常完成后60秒再扫描。扫描采用轻量字段和游标分页（页大小100，独立于分配批次大小），队列满时保留游标，下轮继续，遍历结束重置。失败按60/120/240/300秒退避，成功恢复正常间隔。按ID执行不触发集合扫描。

领取与批次事务继续授权→角色→任务/分配锁顺序；数据库时钟确定30秒租约，行锁内验证RUNNING/owner并续租，角色唯一运行约束保留。旧节点无法越过新owner，超长批次持有锁防止并发写入；批次提交后结果决定继续或停止。业务失败暂停，暂停存储失败时保留任务由扫描恢复。

配置前缀`ingot.iam.role-applications`：worker-enabled=true（保留）、fallback-scan-interval=60s（至少10秒）、active-batch-delay=250ms（正值、小于10秒）、queue-capacity=256（正值）。Duration字段、命名常量、构造注入及JavaDoc遵循in-framework。无新持久化模式、主节点或公开API。

停止领取或退出时停止接收和新批次，等待当前批次最多30秒；超时不强制中断正在提交的事务，保留数据库租约用于异常退出恢复。正常关闭取消订阅/定时器并清理提示队列。Redis提示及本地队列都是优化，数据库始终为恢复依据。

Micrometer记录扫描/故障、领取冲突、批次耗时、队列深度及提示丢弃；数据来自现有执行流程，不增加定时SQL。故障WARN限频，普通空扫描无INFO。可以滚动部署，旧节点仍可通过原租约安全执行，但需全部升级才消除每秒轮询；回退保留任务和原017结构。
