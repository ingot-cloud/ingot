# 平台角色分配与委派管理增量（2026-09-28）

状态：approved → implementing。批准依据：jy 于本会话明确要求 IMPLEMENT THIS PLAN，覆盖两端实施；既有主 change 保留 implementing。

## 需求与规则

平台优先。有效委派自动提供受限分配入口，不产生完整治理、业务、角色创建、委派创建或诊断资格。本人业务授权同操作范围并集，委派限制独立；一次分配不得拼接来源。受限记录查询/详情/预览/调整/撤销仅限本人持有的委派；来源、主体、角色版本不可修改。平台不接受部门范围。

人员页简单直接角色管理要求非委派的明确分配资格；替换同时要求撤销资格，并校验目标成员范围。快捷新增与移除均有同事务审计。

委派收窄必须完整重验角色、人群、逐操作范围、期限和既有派生授权；有冲突时原子拒绝，先调整/撤销再保存。委派、组和角色变更与分配事务互斥；关键写最新鉴权，提交后缓存失效。

## 交互

Tab 为角色/角色分配/授权管理员，各自鉴权，仅激活可见 Tab 请求。受限成员先选择授权依据（一条自动选择，多条分页选择），联动固定角色版本、人群、对象和期限；直接治理默认无来源。受限人员页角色只读，快捷分配使用统一入口。

委派操作按应用→资源→操作选择，逐操作上限完整，OBJECT_SET 绑定具体对象。同资源同类型参数可复用，跨资源对象集合禁止复用。平台已实现资源提供搜索分页及已选 ID 回显，未适配资源明确不支持，不改为 ALL。期限编辑用天/小时，Duration 保留秒精度。ISO 瞬时日期必须真实转换 UTC，不把本地字符串直接追加 Z。

## 接口与数据

新增 GET /v1/platform/assignments/context（directRead/directCreate/directUpdate/directRevoke、有效委派数）。新增 GET /v1/platform/assignments/{id}。
新增 GET /v1/platform/assignments/candidates，kind 为 DELEGATION/ROLE_REVISION/MEMBER/GROUP/OBJECT，支持 delegationGrantId、revisionId、parameterKey、actionId、keyword、ids、page/pageSize。服务端始终按当前身份和单一来源过滤，返回最小 Option(id,name,summary,roleRevisionRef,parameterDefinitions,grants)分页，固定版本额外携带 actions 的应用/资源/操作元数据。
新增 GET /v1/platform/delegations/candidates（MEMBER/ROLE_REVISION/OBJECT）与 /v1/platform/authorization/diagnose/candidates（MEMBER/APPLICATION/ACTION/OBJECT），使用同一候选契约但分别验证委派编辑/诊断权限；OBJECT 以实际被保护接口的对象标识查询，响应包含 supported 与 unavailableMessage。不要求先取得通用 CRUD 列表权限。

AssignmentRecord 保留原字段，增补 subjectName、roleName、revisionNumber、delegationSummary、createdAt、grantedBy、effectiveStatus；返回逐条 capabilities。createdAt 为请求当地墙钟，validFrom/validUntil 保留 ISO UTC Instant。授权人批量取最早 CREATE 审计，缺失为空显示未知；添加 assignment_id/change_type/occurred_at/id 审计索引。不以生效时间伪造创建时间或委派管理员伪造授权人。

DecisionSource 使用 assignmentId/delegationId/roleRevisionRef/summary 契约，真实来源和范围，披露受当前操作者限制。诊断仅只读，跳转重新鉴权。

## 2026-09-30 诊断目标增量（已批准）

记录行诊断固定其成员主体，计算该成员所有有效授权的最终结果，并不隔离单条分配；用户组记录无单一成员，不提供行诊断。工具栏诊断由操作者自选成员、应用、操作与可选目标。目标是所选操作作用的资源记录；无目标只判操作，有目标还判数据范围。

平台诊断的成员候选继续受诊断操作的成员范围限制。目标候选按该资源对应的读取操作及其对象范围过滤，不把可诊断成员 ID 当作其他资源对象 ID；诊断提交同样重验目标读取资格与可见性。无读取资格返回空候选，未接入目标查询的资源明确不支持；目标越界按对象不可见处理，不披露原值。现有诊断与候选接口的路径和请求结构不变。

平台委派编辑的角色候选使用独立的两级角色/固定版本分页树，并按委派治理资格鉴权；此查询不产生分配资格。接收成员名单限定管理员可以把允许版本分配给谁，用户组必须非空且全部成员命中名单；业务对象范围仍由每个操作的上限约束。前端可在弹窗内按应用、资源、操作定位上限，但不能省略所选版本中的操作。委派提交与预览继续由后端重验完整集合。

诊断仍一次只接收一个成员或账号、应用、操作及可选目标。`ACTION` 候选保留真实操作 ID 和原始操作名称，在现有可选 `summary` 字段返回所属资源名称；操作候选搜索同时匹配操作名称与资源名称，应用限制、权限过滤、分页和计数一致。前端以“资源名称 / 操作名称”展示并单选，提交契约不变。

## 2026-10-02 角色范围与委派操作交互增量（已批准）

角色版本固定操作及其范围类型；`parameterKey` 仅为角色定义和分配绑定之间的内部引用。平台角色和共享角色发布时不绑定具体对象或部门；平台角色的对象在平台分配时确定，共享角色的管理部门与对象在租户分配时确定。现有角色定义、分配和委派提交 DTO 保持兼容。新范围参数按资源与绑定类型生成稳定键；未改变的既有范围沿用原键，旧版本与旧分配不改写。平台角色不允许部门范围。

委派所选版本的全部操作只读展示，仍须逐操作配置范围上限，不能从委派中排除操作。平台委派现有对象候选、对象真实 ID 校验和预览契约沿用；界面改为“委派信息→完整操作确认→逐操作上限→预览保存”。

新增 `GET /v1/tenant/assignments/scope-candidates`，参数 `revisionId`、`parameterKey`、`keyword?`、`ids?`、`page=1`、`pageSize=20`，响应复用 `AuthorizationCandidatePage`。参数定义决定部门或对象类型；只在可信租户域、当前分配管理资格、固定版本及参数引用内查询。服务端按目标资源实际受保护接口使用的标识注册候选适配器；跨资源共用旧参数键仅在目标对象类型一致时支持。未注册或含义冲突返回 `supported=false` 与明确原因，不允许回退为裸 ID 或 ALL。预览与创建/修改再次校验绑定键、类型、租户归属、真实对象和当前委派限制；历史记录保持可读，新写入失败关闭。

验收拆分：角色新建与发布无手填参数、旧键兼容；平台委派多版本并集及完整上限；平台和租户对象/部门跨页选择与回显；租户越界、无权、未知适配器及直接请求无效 ID 被拒绝。开发与自动化完成不代替真实 HTTP/浏览器验收。

## 2026-10-02 平台委派向导展示与期限说明（已批准）

创建和编辑平台委派沿用创建角色的全屏、左侧步骤导航与固定底部操作区。完整操作确认只读展示角色版本操作并集，采用角色详情权限 Tab 的应用/资源/操作层级；逐操作上限和预览沿用角色向导的内容布局，但委派允许的多个范围和对象选择规则保持不变。委派 `validFrom`、`validUntil` 仍可空，分别表示无起始与结束边界；`maxAssignmentDuration` 必填且为正。界面应分别标注和校验，不能把三项合并标为必填。由委派派生的单次角色分配仍须有截止时间并受最长时长约束。现有 DTO、接口、后端校验及历史数据不变；前端开发完成与浏览器人工验收分别记录。
# 2026-10-02 平台角色分配与范围选择增量（已批准）

平台应用没有部门模型。目录资源的范围能力仅是角色可用的预设，并不直接成为委派上限；委派上限只针对所选固定角色版本实际包含的操作。平台应用资源创建/修改拒绝 MEMBER_DEPARTMENTS、MANAGED_DEPARTMENTS；历史误配能力保持可读，须显式编辑移除，不能据此创建平台角色或委派。租户应用部门能力不变。

平台成员详情使用独立的角色分配关联列表和逐条能力；新增角色使用固定版本分配接口，参数化版本须选对象，简单版本可以直接分配。旧 roleIds 快捷接口仅允许最新版本无参数，保留既有客户端。平台成员创建新增 roleAssignments 草稿，绑定固定版本与 scopeBindings，成员、组、全部角色在同一事务写入，失败整单回滚；与 roleIds 重复角色拒绝。新建成员角色候选取最新已发布版本，提交期间若版本变化须返回冲突，不静默升级。委派来源不允许通过人员页快捷路径绕过。

平台分配与委派对象候选、租户分配管理部门候选支持树形语义：真实层级资源按父节点分页、全树搜索和已选 ID 回显返回 parentId、hasChildren、ancestorPath；平台菜单和租户部门使用树，其他资源保持列表。受限委派只允许子菜单时，服务端可返回其祖先用于导航，但祖先 selectable=false，不得选择或提交；搜索和已选回显仍只返回允许的实际对象。候选、回显及提交均须处于同一身份和授权上下文；未知适配器 fail-closed。MEMBER_DEPARTMENTS 按成员任职计算，不手选；MANAGED_DEPARTMENTS 仅租户可选。授权管理员委派期限可空，但单次派生分配必须有限且不超过 maxAssignmentDuration；完整治理者直接分配可以长期有效。

验收：平台误配不能新增、历史可识别并手工移除；普通及参数化角色在成员创建/详情准确生效，旧 roleIds 不生成缺参分配，事务失败无孤立成员；树候选搜索、分页、回显与对象越权校验一致；完整治理和仅持委派管理员各自仅能操作其边界；分配步骤预览失效和期限约束准确。
