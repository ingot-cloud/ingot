# Design

## 主键与应用

权威003中接收成员表末尾追加 id BIGINT UNSIGNED NOT NULL（中文说明）及 PRIMARY KEY(id)。IamDelegationRecipientMemberEntity 使用 BigInteger/IdType.INPUT。平台 DelegationService 和租户 TenantLiveDelegationService 通过现有 IamAccess.nextId() 分配并传至实体或手写 Mapper INSERT；不改全局 IdentifierGenerator。原租户/管理域条件保持，不新增按裸行ID绕过归属的操作。

## 历史升级

027先添加可空id作为可恢复中间态，再于一个事务锁定 biz_leaf_alloc 的 iam 行，按待填行数N预留 [原max_id, 原max_id+N)（Leaf的max_id为已预留区间的排他上界）。临时映射按 delegation_id/member_id 排序，ROW_NUMBER分配ID。高水位更新及关系回填同一事务提交；之后将id收紧非空并建立主键。空表无需消费号段。拒绝缺少iam发号标签、非正高水位、超出Long正数范围或未知结构。需停止全部节点及所有写入，恢复时重启节点，避免继续使用旧进程缓存；不把ID当时间或提交顺序。

显式选库的工具默认只读，--apply必须同时--writers-stopped。先核对两表及发号器定义，再执行027及已验证的028；允许原始/可空列/已完成三种主键状态及索引存在/已删除两种状态，未知漂移停止。DDL不是整批事务；事务中断回滚发号和填充，提交后DDL中断可重跑，不重复分配已填ID。记录步骤输出。不关闭外键、不使用force。

## 索引决策门禁

对password_history当前真实SQL做固定数据集、预热、多轮对照：原索引可见、不可见、删除后三态；覆盖按用户查询、最近历史、覆盖槽位、插入和删除。记录EXPLAIN ANALYZE/JSON、扫描行数、耗时和索引页体积。按用户读取全部历史保持用户索引定位；最近历史允许保留原有created_at索引有界倒序/过滤路径，不能因删除新增全表扫描；结果一致且无稳定可复现退化，才删除idx_user_id。不可见阶段仍维护索引，不能用于证明写入收益。使用多用户规模及倾斜历史分布，不新增其他索引或修改服务行为。

## 工件与026隔离

冻结026 SQL及原结构基线（包含SQL摘要），026工具只针对该版本，最新字典/结构快照独立生成；当前DDL不再重写026。预检最新结构的摘要校验继续保留。新库直接manifest构建，不重放026/027/028。最新字典字段数495，表数63；评估报告更新两项已实施结论并修正密码历史消费入口证据。

## 发布与回退

尚未补注释的旧库先按026基线完成026；停写备份→新迁移只读预检→027/028→全部新后端→冒烟验收。旧代码不会填id，禁止迁移后恢复旧节点或只回退应用。结构回退先停止全部新写入，恢复idx_user_id，再在确认id无入向引用后移除新增主键/id；保留业务唯一键/外键/CHECK，永不降低Leaf高水位，然后启动旧应用。提供只接受已知结构的回退工具；DDL失败保持停写并按已知状态修复或重跑，不承诺整批ROLLBACK。
