# Requirements

## 用户场景

1. 租户管理员填写姓名、手机号、可选邮箱和部门后提交。该手机号没有全局账号时，系统创建账号并返回一次性初始密码。
2. 该手机号已有唯一有效账号时，系统把该账号加入当前组织，不改写账号凭证，不返回密码。
3. 手机号对应多个账号、账号已停用、或该账号已是本组织成员时，系统拒绝并给出明确原因。

## 业务规则

1. 手机号是账号标识，提交 11 位大陆手机号，不含国家码。
2. 新建账号时登录名与登录手机号都使用该手机号，初始密码由安全框架生成，创建来源为管理员创建。
3. 已有账号时不修改账号资料、密码或启用状态。
4. 成员通讯录同时写入提交的手机号和邮箱。
5. 部门可空；第一个部门为主部门。
6. 权限仍为 `TENANT_MEMBER_CREATE`。未知字段拒绝。
7. 错误文案面向操作者，不暴露正则、字段名或框架默认校验句：
   - 手机号格式：「手机号格式不正确」
   - 多个账号：「该手机号对应多个账号，请联系平台管理员」
   - 已停用：「该手机号对应的账号已停用」
   - 登录名占用：「该手机号已被其他账号用作登录名」
   - 已是成员：「成员资格已存在」

## 边界与非目标

- 平台成员创建仍按账号 ID 关联。
- 已离职成员再次加入仍报「成员资格已存在」，本次不恢复。
- 不处理邀请、短信下发或批量导入。

## 验收标准

- [x] 无账号时创建账号和成员，并返回 `accountCreated=true` 与初始密码
- [x] 已有唯一有效账号时只创建成员，`accountCreated=false` 且无密码
- [x] 多账号、停用、登录名占用、重复加入返回约定文案
- [x] 平台创建成员接口不受影响
